# 学员进阶模块：给自己的影视工作台加入 3D 空间预演

版本：v1.0 · 2026-10-17

适用于已经用第一版提示词搭建好基础工作台的学员。本模块用于理解空间、安排机位、比较构图，不要求制作精细模型或写实渲染。

**使用方法**：先保存并导出自己的项目，让能够读写项目文件的智能助手打开原工作台文件夹，再将下方“提示词开始”至“提示词结束”完整发送给它。没有基础工作台时，请先完成第一版，不要让助手同时重建两个系统。

这份提示词是一份实施要求，不是已经做好的软件，也不承诺任何助手一次就能完成全部功能。建议先完成第一阶段，再根据实际体验继续。

---

## 提示词开始

请在我**现有的影视创作工作台**中加入一个轻量的 3D 空间预演模块，帮助我理解人物、道具、房间和摄影机之间的关系，并将机位参考带回原有分镜与制作流程。

先读当前目录的 AGENTS.md、README、实际页面代码和正式项目数据。识别现有项目、场次、镜头、修订及保存方式，报告你将修改哪些文件，然后在已有授权范围内实施。不要重新建站，不要用一个独立的三维演示页面代替集成，也不要覆盖我的创作资料。

第一版提示词中“不做三维”的范围，在本模块内调整为允许下述基础空间预演；其他数据保护、离线、权限和真实验收要求继续有效。

### 1. 先把目标说清楚

这个模块主要回答四个问题：

1. 人物和道具在哪里，它们的前后、左右、距离和朝向是否合理？
2. 摄影机站在哪里，实际能看到哪些物体，哪些会被遮挡？
3. 不同镜头的景别、机位、视线和画面关系是否连贯？
4. 我如何把已确认的空间与机位，保存下来交给下一位智能助手继续工作？

它不是建模软件、游戏引擎或电影特效系统。首版不做精细人脸、骨骼动画、布料、物理碰撞、自动生图、生视频或复杂后期。简单人形不能证明眼神准确，静态预演不能证明表演、运动和声音已经成立。

先从当前一个场次、一个镜头开始。只需向我确认尚不明确的关键条件：场次、主要人物与物体、已知尺寸或位置关系。没有明确尺寸时，先提供标注为“暂定”的可编辑方案，不把估计写成已确认设定，也不要因为没有人物模型或图片而停工。

### 2. 分三步完成，不一次堆满功能

**第一阶段：能搭、能看、能保存。**

- 在原工作台进入真实 3D 视图。
- 用基本几何体摆一个房间、一个人物、一个主要道具。
- 自由查看场景，建立一个与实际镜头绑定的摄影机。
- 比较自由视图与摄影机画面。
- 修改位置或机位，导出草稿，由助手保存到正式资料，再关闭重开验证。

**第二阶段：能用来设计镜头。**

- 加入选取、移动、旋转、尺寸调整和数字拖动。
- 摄影机编辑默认锁定，解锁后才能改变机位。
- 增加可读的俯视机位图、实际镜头缩略图和参数面板。
- 支持多镜头切换、撤销与重做、构图参考图和空间简报导出。

**第三阶段：独立检查。**

另用明确标注的虚构示例验证多项目、多场次、不同数量镜头和完整保存恢复。每一步完成后给我可打开的入口、最短操作步骤、已验证内容及开放项，不用按钮数量或代码长度代替交付。

### 3. 延续现有导航和视觉风格

保留 Project、Story & Script、World & Character、Shot Planning、Production、Assets、Review & Learn 七阶段。

将 **Spatial Studio** 放在 **Shot Planning 内部**作为一个视图。如果已有 Shot List 或 Storyboard，就在页内平级切换；不要在主导航中插入一个没有编号的额外阶段，也不要给普通页内切换加表示外部跳转的斜箭头。进入 3D 时，左栏仍选中 Shot Planning，下一阶段仍是 Production。

采用原工作台的中性深灰背景、细边框和少量青绿强调。操作按钮使用清楚的英文标签，说明、创作内容和帮助使用中文。沿用已有字体、字号、Audience 模式和焦点样式，不引入另一套亮色界面或装饰性控制台。

进入 3D 后持续显示当前项目、场次、镜头和是否有未保存草稿。教学示例与个人项目分开，个人场景不能继承教师示例的房间、三镜头数量或素材。

### 4. 使用真实的轻量 3D，实现方式服从现有环境

优先复用项目已有的浏览器 3D 库；没有时可以提出使用 Three.js 等开源库的最小方案。不要用一张静态图片、伪透视 CSS 或视频冒充可操作的三维场景，也不要为了少依赖而临时手写一套不可靠的三维引擎。

库及资源应放在项目内、固定版本、保留来源和许可证。若需要联网获取依赖，先说明具体来源、文件与用途并取得我的同意；不要下载大型模型、安装 Blender/游戏引擎、申请账号、上传资料或调用付费接口。

**开发时获取依赖与运行时联网是两回事。** 交付后运行资源必须本地可用，不依赖 CDN、外部字体和在线模型地址。

- 如果现有脚本与本地库确实支持双击打开，保留这个入口。
- 如果采用 ES module、模型加载等功能而需要本地 HTTP 服务，请提供只绑定 `127.0.0.1` 的启动方式，并明确需要哪个已经安装的运行环境、如何停止；不要暴露到局域网。
- 不得仍声称这种模式可以仅靠双击 HTML 完整运行。基础工作台已有的非 3D 功能也应继续可用。
- 浏览器不支持 WebGL 或上下文丢失时，显示明确说明，保留项目编辑与保存入口，不黑屏、不丢草稿、不自动上传到云端替代。

### 5. 第一版场景只需要基本物体，但比例与朝向必须可信

至少支持：地面、墙体或房间边界、门窗位置标记、方体、柱体、球体、简化人物和摄影机。桌子可由简单桌面和支撑组成，电脑可以是能辨认正反面的屏幕块。

无需细致还原材质，但必须能看出：

- 人物面朝哪里；显示器正面朝哪里；门在哪面墙上。
- 人物、桌子、门的实际前后关系。
- 桌高、人物高度、房间和道具尺寸的基本比例。
- 实体物体的遮挡关系，不能为构图好看而让桌子或墙壁自动消失。

人物先用带有正面标记的简单人形即可，不要求老师的人设或外部人物模型。物体不能有无意义的重复网格、穿模辅助块或难以识别的背面。允许有意放置交叠，但应让用户能发现并修正，不需要实现物理碰撞引擎。

空间以米为单位，界面可以显示米或厘米，但保存时统一单位。约定 `+X` 向东/右、`+Y` 向上、`-Z` 向北；俯视图上方对应北。若已有项目使用另一套坐标，就沿用并明确展示，不能混用。人物局部正面、旋转方向和角度单位也要写入维护说明。

墙体可以在**自由观察视图**中提供明确的隐藏/淡化选项，方便查看内部；摄影机参考图默认使用真实场景的墙体与遮挡。需要剖视时必须标注，不能把剖视结果当正常机位参考。

### 6. 自由视图与摄影机视图必须明确分开

**Free View：观察整个场景。**

- 左键拖动环绕观察目标。
- 右键拖动平移，画面中的场景跟随鼠标移动，不出现左右反向的手感。
- 滚轮改变观察距离，不改任何正式摄影机的焦距或视角。
- 切换当前镜头时不要偷偷把自由视图当成摄影机画面；另提供 Frame Selection / Frame Scene 取景。

**Camera View：显示当前镜头的实际构图。**

- 默认 Locked，普通查看不会改坏机位。
- Unlock 后才能拖动或修改摄影机参数，并持续显示解锁状态。
- 左键改变观看方向，拖动的画面反馈应与自由视图一致；明确它不是绕同一个场景中心转圈。
- 右键在摄影机自身的画面平面内平移，位置与目标一起移动，不悄悄改变朝向；画面反馈与自由视图一致。
- 滚轮改变 FOV，保留摄影机位置；页面旁直接说明“Free View：滚轮改观察距离；Camera View：解锁后滚轮改视角”。
- 锁定时，鼠标、滚轮、数字编辑和操纵柄都不能改机位，不能只锁住其中一种操作。

保留 Touchpad 或没有鼠标时的按钮/数值操作。提供 Reset View 与 Reset Layout，放在视图区附近；它们分别恢复观察视图和面板布局，**不重置场景、不覆盖镜头、不删除草稿**。恢复场景初始状态是另一项操作，必须先保留当前草稿并明确确认范围。

### 7. 参数与选择操作应像一个可以长期使用的工具

- 点击选择物体，显示名称和清楚的选中反馈；区分单击选择和拖动旋转，不要松手就误选。
- 提供 Move / Rotate / Scale；首版可以先做好数值编辑，再增加操纵柄，不显示未实现的按钮。
- 参数按 Transform、Dimensions、Camera 等分组，展示单位与可接受范围。
- **数值可以水平拖动调整**，按 Shift 精调；双击进入键盘输入，Enter 确认、Escape 取消。保留直接输入，不强迫所有参数都用滑块。
- 一次连续拖动是一个撤销步骤，不能每移动一像素就塞入一条历史。
- Undo / Redo 支持撤销物体和机位编辑；场次或项目变化不能串用另一份撤销历史。
- 拒绝 NaN、无穷、非正尺寸和不合理的摄影机裁剪范围；不能用错误数值把整个视图变空。
- 操纵柄、坐标轴端标签在远近变化时保持可操作的屏幕尺寸，轴线与标签比例协调，不能三个大字把轴全部遮住。
- 变换、选择和编辑锁发生冲突时，给出一种确定行为，不让两个控制器同时响应同一次拖动。

### 8. 摄影机和机位图共同表达同一份资料

每个实际镜头可以绑定一个 3D 摄影机。镜头数量来自项目数据，不能写死成三个。用稳定的 shotId 对应，不按屏幕第几个镜头猜关联；删镜头或删除它引用的物体时先说明影响，不静默删引用。

摄影机至少有位置、观看目标、画幅比例、垂直 FOV、near/far 裁剪面。位置与目标是数值来源；朝向或俯仰面板如有显示，须由同一套变换规则计算，不能另存一份会漂移的角度状态。需要上下俯拍时明确处理目标与摄影机重合、接近垂直方向等退化情况。

若提供焦距毫米值，必须注明传感器假定，并从焦距、画幅和传感器尺寸一致地换算视角。不要把焦距、水平视角和垂直视角当三个互不相关的可编辑值。近远物体大小关系由机位与投影自然形成，不用“改 FOV”冒充摄影机前后移动。

布局至少包含：

1. 足够大的主视图，可明确切换 Free / Camera。
2. 可展开的 Top View：房间轮廓、人物朝向、主要道具、摄影机位置与视锥；能看清标签，不做一个无法操作的小装饰。
3. 当前镜头的参数面板和场次/镜头切换。
4. 多镜头缩略图：由各自摄影机实际渲染，标注镜头名与采用的画幅。缩略图是预演，不冒充生成结果。

机位图、主视图和缩略图读取相同几何与摄影机资料。修改一处后其他视图同步；地图拖动如果未实现，就明确为只读，不能看起来能拖却没有作用。

### 9. 扩展原数据，不建立第二个互相冲突的项目源

先识别现有 schema；以下是字段职责，不要求推翻已有结构。

- 每个场次新增可选的 `spatial` 数据：版本、单位/坐标约定、场景修订、物体列表、光照和必要预演设置。
- 每个物体具有稳定 id、类型、名称、位置、尺寸、旋转、可见性和可选的人物/地点引用。旋转规则必须统一，不能混存未注明单位的角度与弧度。
- 每个镜头新增可选的 `camera3d`：场景归属、摄影机位置/目标、投影与画幅、裁剪设置、锁定状态、可选的目标物体引用。
- 原有镜头叙事、文字机位说明和原始材料保留。数字机位变化时，生成新的“空间简报”或待确认建议，不悄悄改写我的原始文字。
- 镜头顺序继续以 `scene.shotIds` 为准。项目、场次、物体和机位归属均需验证，不把第一场的房间套进另一场。
- 旧项目没有 `spatial` 时仍能正常打开。升级前备份；不因缺少 3D 字段而删掉旧字段、素材、任务或尝试。
- 首版按场次保存空间。地点共用几何的能力可以后续再做，不能先共用一个可变对象，导致修改甲场次连带改变乙场次。

草稿、正式文件和导出备份继续沿用第一版的保存协议，不新建一套隐蔽的三维“正式数据库”。浏览器自动缓存如有，只能用于恢复草稿，不能成为唯一资料来源。

### 10. 保存与恢复必须真的走通

网页编辑产生当前项目/场次草稿，清楚标记 Unsaved Changes。Export 导出严格 JSON，包含 schema、projectId、sceneId、baseRevision、草稿修订以及恢复所需的完整物体、摄影机数据。

如果是单场次导出，必须明确它是**部分补丁**而非完整项目：导入/保存时只能受检更新这一场及其机位，不能把包内没出现的其他场次、镜头或素材当成已删除。

Import 必须先验证结构、版本、数值、对象和镜头引用、归属、资源路径与旧历史；整体通过后再一次性应用。失败时当前视图和数据都保持原样。用户文字仅作为文字，不能通过导入执行脚本或远程请求。

写回正式 `data/project.js` 仍由有权限的助手完成：比较当前版本与导出基准，报告冲突，先备份再保存，再刷新/关闭重开验证。不能用文件时间猜新旧，也不能只导出后就宣布“已经保存到项目”。

原有 Attempt 的实际提示词和输入快照不可重写。修改 3D 资料不等于修改历史生成时使用过的那张参考。

### 11. 让 3D 真正回到创作流程

提供两个输出：

**Export Frame：当前镜头参考图。**

- 必须从该 shotId 对应的摄影机渲染，采用当前画幅；不能误导出自由视图。
- 默认不带网格、操纵柄、机位图和界面遮挡；另保留可选辅助线版本。
- 一并导出可读的说明或 JSON，记录项目/场次/镜头、正式与草稿修订、空间版本、机位、目标、FOV、画幅和暂定条件。
- PNG 与说明使用可关联的文件名。浏览器下载到哪里并不代表已进入项目素材目录；由我或助手放入目录并确认文件后，才能按实际安全相对路径登记到 Assets。
- 登记为当前镜头的 **3D reference**，不是采用的生成静帧，不自动设为 selectedStillId，不自动解锁 I2V 的“已选静帧”条件。

**Copy Spatial Brief：空间制作简报。**

- 以普通语言描述镜头叙事任务、机位、景别意图、人物/道具朝向、前后关系、实际遮挡和画幅。
- 精确数值与暂定估计分开；无法根据简化人形确定的眼神和动作，明确标记待确认。
- 说明参考分工：3D 图主要约束空间、视点和遮挡；人物图约束外观；场设图约束美术与光照。若参考互相矛盾，先列冲突并确认，不同时要求全部照搬。
- 交给 Production 时仍通过原来的共用制作说明函数组合，不另造一套会与镜头资料脱节的万能提示词。

3D 参考或截图只是新参考资产。没有真实模型调用、结果和复盘时，不新增“成功生成”的 Attempt。

### 12. 保持普通电脑可用，并能交给下一位助手

使用简单网格与克制的照明。按电脑能力限制像素密度和阴影开销；没有运动时按需重绘。缩略图按需更新，不让每个镜头都启动一条全速动画循环。

离开 3D、切项目或切场次时，停止无用的渲染循环，移除旧事件监听并释放不再使用的 GPU 资源，保留仍需恢复的草稿。反复进入不能越来越卡，也不能同时有两个控制器响应鼠标。不要为了导出图片无限提高分辨率导致页面崩溃。

更新原有 Copy Agent Brief，使其包含当前项目/场次/镜头、数据版本、未导出状态、3D 变更和待确认的空间问题；提醒下一位助手先读已有文件和草稿，不重建模块、不套用教师示例。

更新 AGENTS.md 和 README，解释坐标/单位、控制方式、锁定、暂定尺寸、素材职责、数据保存、回滚和实际测试。说明应给普通创作者看得懂，不要求我理解图形学术语后才能保存项目。

### 13. 用实际操作验收

除检查代码外，至少验证下列场景；无法实测的明确列出，不能写成已经通过。

- 原有基础工作台、旧项目和没有 3D 数据的场次仍可打开。
- 在自己的虚构示例中建立“人物—桌子—门”，人物与屏幕朝向可辨；从两个机位看，遮挡与透视真实变化。
- 自由视图移动不改变正式机位；摄影机锁定时，拖动、滚轮、数字和操纵柄都不会改机位。
- 解锁后改 FOV 不改变位置；平移不改变朝向；两种视图没有明显相反的拖动手感。
- 数字拖动、直接输入、精调、取消、一次撤销与重做有效；错误数值不会破坏场景。
- 俯视图、参数与实际镜头缩略图一致；支持两个场次、不同数量镜头，不串资料。
- 切换场次前处理未导出草稿；导出→导入→助手更新正式资料→关闭→重开后，物体、机位、锁定、修订与镜序保持。
- 旧版本冲突、重复 id、跨场机位引用和错误导入被拒绝，不清空当前场景或其他项目。
- 导出图与当前 Camera View 一致，画幅正确、没有编辑操纵柄；参考图登记不会冒充生成结果。
- Reset View / Reset Layout 不改变场景；移动整个工作包后资源仍可定位。
- 断网可运行；不支持 WebGL 时基础功能及保存仍可用；多次进出 3D 后没有明显重复循环或持续性能恶化。

最后告诉我：已经做到第几阶段、从哪里进入、怎样解锁和保存、哪些是暂定参数、哪些交互真正测过、下一位助手如何继续。先交付能保存和恢复的基础 3D 工具，再考虑精细人物、运动预演或更复杂的扩展。

## 提示词结束

---

给学员的建议：第一轮先证明“一个物体的位置变化，会正确改变两个机位看到的画面，并且能保存重开”。不必先追求漂亮模型；可靠的空间、镜头关系和资料接续，才是这个进阶模块的核心。
