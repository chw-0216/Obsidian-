操作手册 · 五步走完

全程只需要一次配置，之后备份新项目就是复制粘贴。

阶段一 · 配好钥匙（一次性，约 5 分钟）

  1. 把公钥交给 GitHub。打开 github.com/settings/keys → 点 New SSH key → Title 随便填（如「我的笔记本」）→ Key type 选 Authentication Key → 把下面这一整行粘进去 → 点 Add SSH key。 
    ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIC94EDOaEEmgfTCA6GQpeXzMuFBnJZHIYkfJVkpYR2k kayleigh_teneturzy@protestant.com
  2. 修正 Git 身份。你现在的全局邮箱是个占位假邮箱，提交记录会认不出是你。改成 GitHub 账号的邮箱： 
    git config --global user.name "你的GitHub用户名"
git config --global user.email "你的GitHub邮箱"
  3. 验证连通。 
    ssh -T git@github.com
    看到 Hi 用户名! You've successfully authenticated 就成功了。

阶段二 · 建立你自己的仓库

  1. 打开 github.com/new。
  2. Repository name 填 opensource-backup。
  3. Visibility 选 Private（你自己的备份，不必公开）。
  4. 勾上 Add a README file，点 Create repository。

阶段三 · 备份项目：两条路一起走

路线 A · Fork（云端复制）——打开项目页，点右上角 Fork → Create fork。项目就整份进了你的账号，原库删了你的还在。

路线 B · 镜像克隆（本地存档）——完整拉下所有分支和历史：

git clone --mirror https://github.com/owner/repo.git

阶段四 · 推送到自己的私有仓库

镜像仓库推上去，才算真正「有主」：

cd repo.git
git remote set-url --push origin git@github.com:你的用户名/repo.git
git push --mirror

阶段五 · 长期维护

上游更新时同步一次即可。这份手册会配套一个一键同步脚本，放在同目录下，双击就能跑。

一个提醒：Fork 和镜像备份都只覆盖代码。很多项目的大模型权重、训练数据、艺术素材是另外分发的，不在 Git 仓库里。对这类项目，还要单独把模型文件存一份到移动硬盘。
为什么建议两条路都走：Fork 依赖 GitHub 账号可用；本地镜像依赖这块硬盘。两者互为备份——GitHub 被墙、账号被封、硬盘损坏，任何单一故障都不会让你彻底失去项目。
