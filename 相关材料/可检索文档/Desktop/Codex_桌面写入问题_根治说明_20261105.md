## 一、结论（先看这里）

Codex「写不了桌面」**不是系统故障，也不是权限配置坏了**，而是**那个对话单独使用了"限制范围"的权限档**：

- 你的全局配置本来就是最高权限：`approval_policy = "never"` + 默认权限档「完全访问」（已核实）。
- **2026-11-05 已显式设置默认权限档**：按官方配置参考把 `sandbox_mode = "danger-full-access"` 替换为 `default_permissions = ":danger-full-access"`（两者按文档不应并存），新对话默认即「完全访问」。备份：`~\.codex\config.toml.bak-dsh-fullaccess-20261105-160908`。**需完全退出 ChatGPT 应用再重开生效。**
- 实测：用 Codex 自己的沙箱以「完全访问」档写桌面 → **成功**；以「工作区」档写桌面 → **被拒（Access denied）**，写工作区内 → 成功。
- 选片那个对话（"2c 青年实验空间 / 天海山选片"）走的是受限档，且它的权限提升弹窗被禁用，所以 Codex 只能老实说"当前环境不能直接写入桌面目录"，把照片打包成 zip 让你自己下载解压。

## 二、根因（证据链）

1. ChatGPT 桌面端在 Windows 上使用 `unelevated` 沙箱（本机是 Win11 23H2，不支持新版 MXC 沙箱），靠**每个对话专属的权限 SID + 文件夹 ACL** 圈定可写范围（`~\.codex\cap_sid` 可查）。
2. 对话记录里 Codex 原话："桌面不在可写范围。不得改用其他工具绕过该限制"、"you cannot ask for escalated permissions if the approval policy is Granular(...)"——说明该对话的审批策略是 **Granular（按范围授权）**，模型不能自行申请扩权。
3. 另有"云端环境"阶段：电脑连接中断时该对话会切到云端，本地 PowerShell / E 盘 / 桌面都不可用，这是另一种"写不了桌面"的来源。
4. 桌面文件夹 ACL 里有一些历史遗留条目（Everyone 拒绝删除子项、若干无法解析的 SID、Low 完整性标签等），实测**不影响**正常读写和删除，不必动。

## 三、根治操作（在 ChatGPT 应用里，约 30 秒）

1. 打开那个选片对话（标题含"2c / 照片 / 天海山"的对话）。
2. 确认右上角/输入框附近显示的是**本机模式**（已连接你的电脑），不是云端。
3. 点对话的**权限设置**，把档位改成 **「完全访问」**；
   或者保持原档位、把 `C:\Users\wardc\Desktop` **加入可写文件夹**。
4. 对 Codex 说："现在把 zip 解压到桌面" 或直接让它写桌面测试文件验证。

**新对话默认就是「完全访问」**（本次已由 `default_permissions` 显式设定；改动后需完全退出并重开 ChatGPT 应用生效）。只有个别对话被单独设成限制档时才会再遇到这个问题——遇到时按上面第 3 步把该对话改回「完全访问」即可。
