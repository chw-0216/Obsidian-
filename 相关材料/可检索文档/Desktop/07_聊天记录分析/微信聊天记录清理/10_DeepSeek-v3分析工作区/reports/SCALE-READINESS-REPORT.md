## 7. 预算差距分析与可选措施

真实成本约 **21.6M token**，超出 14M 目标约 7.6M。差距构成：

- **输出 13.8M（64%）**——由所需字段（互动功能/intent/边界/情绪/事件/关系/记忆/置信度/evidence）决定，是质量下限，不易再砍。
- **system cache 7.3M（34%）**——每次调用都重发 1,408-token 的 system prompt，随调用次数线性增长。
- 用户内容输入仅 0.48M（2%）。

可选措施（按性价比排序）：
1. **减少调用次数**：提高 `max_units_per_batch` / `max_msgs_per_batch`，让 15 条窗口尽量合批，5,214 调用若减半 → 直接省约 3.7M system cache。
2. **精简 system prompt**：compact prompt 已砍过一轮；若再省去示例 JSON 的长尾，可从 1,408 降到 ~1,000 tok/调用，再省约 2.1M。
3. **接受超预算**：若 DeepSeek 对 `cache_read_input_tokens` 按折扣计费（Anthropic 惯例为输入价 ~10%），则 7.3M cache 实际成本 ≈ 0.73M 等价全价 token，总等效成本 ≈ **15M**，接近 14M。
4. **进一步裁剪输出字段**：与"不降低质量"的目标冲突，不推荐除非用户确认可以舍弃部分字段。

> 若目标"≤14M"是**成本口径**（而非原始 token 数），选项 3 已基本达标；若是**原始 token 口径**，需选项 1+2 组合后重测（预计可到 ~15M，仍略高于 14M，输出为硬下限）。
