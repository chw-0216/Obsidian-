# 启动任务：DeepSeek v3 分层试运行

请先完整阅读本目录 `CLAUDE.md`，然后执行以下任务。

## 当前数据事实

- 数据库副本：`data\wechat-analysis-v3.sqlite3`
- 725 个会话、71,550 条消息、6,303 个片段。
- 旧版和激进版合计只覆盖 227 个不同片段。
- 140 个激进标注全部来自单消息片段，因此历史 119.8K–124K output tokens/min 不能代表中长对话速度。
- 当前只有 2 个完整联系人画像和 4 个时间线摘要。

## 本次目标

建立一个可复用的 v3 执行器，并完成最多 20 个片段的分层真实试运行。不要启动全量运行。

## 执行顺序

1. 只读检查数据库结构、旧执行器和历史说明：
   - `..\01_主项目_WeChat-MiMo-Analyzer\src\async_executor.py`
   - `..\09_未迁移脚本与运行依赖\高吞吐异步标注流程-复现说明.md`
2. 在本工作区创建：
   - `src\deepseek_v3_executor.py`
   - `config\v3_config.json`
   - `prompts\base_annotation.md`
   - 必要的测试和 Schema。
3. 修复旧流程的核心问题：
   - 短片段必须真正合并为一个 API 请求，并逐片段拆分结果；
   - 长片段窗口只发送对应文本，不得重复发送完整 transcript；
   - 并发增减必须真正创建或停止 worker；
   - 队列清空后正常退出；
   - 验证失败、429和超时进入有次数上限的重试队列；
   - 所有成功、失败和未完成项写入 manifest/JSONL；
   - 通过内容哈希、模型和提示词版本避免重复调用。
4. 基础标注尽量在一次调用内输出：主题、摘要、请求、承诺、事件、实体、关系信号、记忆候选、置信度、替代解释和证据 ID。
5. 先完成不调用 API 的测试。确认只会写入本工作区数据库副本后，抽取 20 个片段：单消息、2–3条、4–10条、11–30条、31条以上各4个；优先选择未标注片段。
6. 使用 `deepseek-v4-flash`，并发从4开始，最多8，完成真实试运行。
7. 生成：
   - `reports\PILOT-QUALITY-REPORT.md`
   - `runs\<run-id>\manifest.json`
   - 成功结果、失败结果、Token统计、证据回链率、Schema合格率和各尺寸片段耗时。
8. 完成20个片段后停止，在当前窗口用中文汇报质量、实际Token、速度、问题和全量运行建议，等待用户决定是否扩大规模。

不要修改 Claude 全局设置，不要输出 API Token，不要清理旧文件。
