## 三、并发与稳定性

Claude Code 应根据接口实际表现动态调整，而不是写死高并发：

1. 从 8 个并发 worker 开始；
2. 连续 10 分钟没有限流且延迟稳定，可逐级尝试 12、16、24、32；
3. 出现 429、超时率超过 5% 或错误率明显上升，立即降低一级；
4. 每个片段完成后立即落盘，不等待整批结束；
5. 失败项进入独立重试队列，成功项永不重复调用；
6. 每次调用记录输入哈希、模型、提示词版本、用量、耗时和状态；
7. 到期前至少预留 30 分钟停止新任务、完成写盘和生成总清单。

## 四、时间不足时的取舍

| 剩余时间 | 必做 | 暂缓 |
|---|---|---|
| 少于 2 小时 | P0 全量观察；能做多少联系人记忆就做多少 | 数字分身扩展、合成问答 |
| 2—4 小时 | P0＋P1＋P2 | 深度角色扮演和第二视角复核 |
| 4—8 小时 | P0—P4 | 大规模对抗测试 |
| 超过 8 小时 | P0—P5 | 只有核心资产完整后才扩展合成数据 |

若速度不足，宁可每个联系人有一份可追溯的基础记忆，也不要只把少数联系人分析得极深而大部分完全没有覆盖。

## 五、推荐额度分配

不按固定 Token 数，而按当前剩余额度动态分配：

| 任务 | 比例上限 |
|---|---:|
| 全量片段观察和事件提取 | 20% |
| 联系人关系记忆 | 20% |
| 个人记忆与人生时间线 | 15% |
| 沟通模式与角色扮演 | 15% |

| 独立复核、反证和事实裁判 | 10% |

这是上限，不要求机械花完。某阶段完成并通过抽检后，额度转给后续阶段。
