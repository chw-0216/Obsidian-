# 微信个人记忆系统＋沟通教练＋数字分身：三位一体实施蓝图

> 路线已确定：三个方向全部实施。本文是交给 Claude Code＋小米 MiMo Token Plan 的总体蓝图。当前只设计，不读取或分析聊天正文。

## 一、总原则

三个方向不是三个独立项目，而是一棵树：

```text
微信聊天与其他个人资料
        ↓
证据层：原文、时间、人物、消息 ID
        ↓
个人记忆系统：事件、事实、关系、偏好、项目、表达风格
        ├─ 沟通教练：发现模式、模拟场景、设计行为实验
        └─ 数字分身：检索记忆、辅助表达、讲述经历、回答问题
                ↓
用户确认与纠错重新写回记忆系统
```

核心约束：

1. 只有一个记忆库，沟通教练和数字分身不能各建一套互相矛盾的画像。
2. 每个事实、事件、模式和建议都能回到消息 ID 或用户确认记录。
3. 原文、观察、模型推断、用户确认四种状态严格分开。
4. 全量聊天可提交给 MiMo，不脱敏、不隐藏联系人姓名；仍需分段和分层，以提高理解质量并控制重复调用。
5. 数字分身可以学习全部聊天，但不得把模型推断伪装成本人亲口确认的观点。
6. 当前阶段只让 Claude Code搭建框架；用户明确切换运行模式后才开始分析。

## 二、统一系统结构

### L0：原始证据层

只读保存 WeFlow 导出的聊天记录，记录来源文件、会话、联系人、时间、消息 ID、发送方、消息类型和原文哈希。任何清洗不覆盖原始文件。

### L1：标准化与检索层

负责：

- 统一时间、发送方和消息类型；
- 去重、连续对话分段、媒体占位；
- 联系人稳定 ID 和备注名历史；
- 全文检索、时间检索、联系人检索和主题检索；
- 增量导入，只处理新增或变化内容。

这一层尽量使用确定性程序，不浪费 MiMo 调用。

### L2：观察与事件层

MiMo 对每个对话片段提取可核对信息：

- 主题、请求、决定、承诺、待办、会面、冲突和修复；
- 双方明确表达的需求、偏好和边界；
- 可观察的语气与互动行为；
- 每项结果对应的证据消息 ID、时间和置信度。

这一层只回答“聊天里明确出现了什么”，不直接下人格结论。

### L3：个人记忆系统

把多段观察合并成可长期更新的记忆：

| 记忆类型 | 内容 | 示例 |
|---|---|---|
| identity | 稳定身份事实 | 经历、职业、长期角色 |
| episodic | 带时间的经历 | 一次合作、旅行、冲突、转折 |
| semantic | 从经历中确认的知识与观点 | 对摄影、金融、AIGC 的理解 |
| relationship | 与具体人物的关系上下文 | 相识过程、共同事件、互动习惯 |
| preference | 喜好和习惯 | 表达、审美、工作方式 |
| current_state | 当前状态 | 近期项目、目标、未完成事项 |
| communication_style | 本人表达风格 | 句式、语气、解释方式、常用结构 |
| uncertainty | 冲突或待确认信息 | 两个版本、证据不足、可能过期 |

记忆不是永久真理。每条都要有：`memory_id`、内容、类型、时间范围、来源证据、置信度、确认状态、最后更新时间、冲突项和过期规则。

### L4-A：沟通改善系统

沟通教练从记忆库读取跨联系人、跨时间的模式，输出：

1. **稳定模式**：在多个场景重复出现；
2. **关系特定模式**：只与某类人或某个关系出现；
3. **情境模式**：只在邀约、冲突、求助、合作等场景出现；
4. **待验证假设**：证据不足，等待本人判断；
5. **行为实验**：下一次可以具体尝试的新做法。

建议采用“观察—影响—替代—练习—复盘”结构：

```yaml
observation: 有证据的当前做法
possible_impact: 可能造成的理解差异，不写成确定事实
alternative: 一项更符合目标的替代行为
example_phrasing: 2-3 个自然表达版本
roleplay: 可与数字分身练习的具体场景
success_signal: 可以观察的改善信号
review_result: 实际尝试后的结果
evidence_ids: 原始证据
```

沟通改善关注清晰、倾听、边界、情绪承接、真实表达、跟进和修复，不把“让对方服从或喜欢”作为目标。

### L4-B：数字分身系统

数字分身分四级逐步成熟：

| 级别 | 形态 | 能力 |
|---|---|---|
| T0 记忆助手 | 私人检索问答 | 回顾人物、事件、决定、承诺和经历 |
| T1 表达助手 | 写作与回复草稿 | 使用本人认可的结构、语气和价值观 |
| T2 互动分身 | 多轮角色与场景模拟 | 沟通演练、人生故事、观点问答 |
| T3 视听数字人 | 声音与形象 | 在单独授权后接入语音和数字形象 |

数字分身的回答必须给内部来源状态：

- `confirmed`：本人明确确认；
- `direct_expression`：聊天中本人直接说过；
- `inferred`：模型根据多个证据推断；
- `unknown`：没有足够信息。

数字分身对外始终说明是 AI；自动替本人发送微信不属于本蓝图默认能力。

### L5：确认、纠错与成长闭环

用户可以对任何结果执行：确认、部分确认、否决、改写、合并、标记过期。反馈分别进入：

- `confirmed_memories`；
- `rejected_inferences`；
- `corrections`；
- `communication_experiment_results`；
- `persona_preferences`。

下一轮分析优先读取这些反馈，避免反复提出已经被否决的判断。

## 三、MiMo 六个角色

同一个 MiMo 模型分六种独立任务运行，提示词和输出 Schema 分开：

1. **观察提取器**：从原文提取事实、事件和证据。
2. **记忆整理器**：合并重复事件，发现更新、冲突和过期记忆。
3. **关系分析器**：形成联系人时间线和互动模式。
4. **自我模式分析器**：跨关系寻找蔡浩文自己的稳定及情境沟通模式。
5. **沟通教练**：生成替代表达、角色扮演和可验证实验。
6. **数字分身构建器／审计器**：提炼 Persona，同时检查事实忠实度和人格漂移。

角色之间通过结构化文件传递结果，不通过一条无限增长的聊天上下文传递。

## 四、推荐多轮执行顺序

### Phase 0：框架搭建

只创建 Schema、提示词、目录、测试、用量配置和运行开关，不分析真实聊天。

验收：合成数据能完整走通，证据 ID 回链测试通过。

### Phase 1：全量基础记忆

对全部私聊进行标准化、分段、观察提取、事件合并和联系人时间线构建。

验收：随机抽查摘要不编造；每项事实能回到原文；重复事件得到合并。

### Phase 2：个人记忆系统

生成个人时间线、人物关系、项目经历、偏好、观点、当前事项和不确定记忆，并提供搜索入口。

验收：能正确回答“什么时候、和谁、发生过什么、证据在哪里”。

### Phase 3：沟通改善

跨联系人分析自己的沟通方式，先给模式草稿，再由本人确认，最后每次只执行少量行为实验。

验收：建议具体、自然、可在真实场景尝试；复盘后能更新判断。

### Phase 4：数字分身 T0—T2

先做记忆问答，再做表达助手，最后做互动分身。Persona 只吸收本人确认或有明确来源状态的内容。

验收：事实忠实、风格稳定、承认不知道、不冒充真人。

### Phase 5：持续增量

以后导入新增微信记录时，只处理变化片段，并更新相关人物、事件、模式和 Persona，不全库重跑。

## 五、效率框架

1. 本地完成解析、去重、分段、计数和检索；MiMo 只做语义理解。
2. 使用 Map—Reduce：片段观察 → 联系人摘要 → 跨关系模式 → 个人记忆。
3. 所有模型结果按输入哈希缓存，提示词未变且原文未变时不重复调用。
4. 长对话按事件边界切分；跨片段信息通过检索补充，而不是每次塞入全部历史。
5. 先低成本全量提取，再对高价值事件、关键关系和冲突记忆深挖。
6. 每批保存进度、失败原因和可重试 ID，Claude Code 中断后可以续跑。

## 六、统一核心对象

Claude Code 至少实现以下七个 Schema：

```text
observation          原文中的单项可观察信息
episode              一段完整事件或互动
memory_item          可长期更新的个人记忆
relationship         人物关系及时间线
pattern_hypothesis   跨场景沟通模式及反证
coaching_experiment  沟通改善实验与复盘结果
persona_rule         数字分身事实、价值观、风格和行为规则
```

所有对象共同字段：

```yaml
id: 稳定唯一 ID
status: observed | inferred | confirmed | rejected | expired
evidence_ids: []
time_range: null
confidence: 0.0
created_at: null
updated_at: null
model_version: null
prompt_version: null
user_note: null
```

## 七、验收指标

- 证据回链成功率：100%；
- 抽检事实忠实度：至少 95%；
- 无证据人格结论进入稳定记忆：0；
- 无关联系人串线：0；
- 被用户否决的判断未经新证据再次出现：0；
- 沟通建议具备场景、示例和成功信号：100%；
- 数字分身严重事实编造或冒充本人：0；
- 所有记忆、反馈和 Persona 均可导出并更换模型继续使用。

## 九、当前唯一推荐顺序

不再三选一，固定按以下顺序推进：

1. **先建立个人记忆系统**，保证所有分析有统一事实底座；
2. **再上线沟通改善**，让系统尽快产生现实价值；
3. **随后生成 T0—T2 数字分身**，让它继承经过验证的记忆和表达方式；
4. **最后再决定 T3 声音、形象和自动化能力**。

这样既保留三个方向，又不会让数字分身在记忆和证据尚未稳定时先学会“像你说话，却不真正了解你”。
