# 小米 MiMo Token Plan：最激进到期冲刺补丁

> 使用方法：把本文“直接追加给 Claude Code 的补丁指令”粘贴在 `04-Token今日到期冲刺执行方案.md` 第六部分之后。冲突项以本文为准。

> 本文负责“跑得激进”。若还要“判断得激进”，请继续追加 `06-最激进分析判断补丁.md`。

## 一、最激进模式的含义

本模式从 `EXPIRY_HARVEST` 升级为 `EXPIRY_HARVEST_MAX`：

- 目标从“完成第一版”改为“在到期前最大化可长期复用的语义资产”；
- 采用动态高并发、流水线重叠和多视角独立分析；
- 核心覆盖完成后，不停机等待，而是自动转向复核、反证、训练语料、问答集和对抗测试；
- 禁止用重复摘要、无意义扩写、翻译循环或填充文本消耗额度；
- 不修改或删除原始聊天，不自动发送微信，不改系统级配置。

## 三、改成持续流水线

原方案不再等待一个 Phase 全部完成才启动下一个 Phase。改为按联系人和数据分片流水线推进：

```text
原文分片
  ├─ 观察提取 ─→ 事件整理 ─→ 联系人记忆 ─→ 沟通分析
  ├─ 风格提取 ─→ 表达语料 ─→ 数字分身风格集
  ├─ 人生事件 ─→ 时间线 ─→ 人生故事问答集
  └─ 独立复核 ─→ 冲突检测 ─→ 证据裁判
```

启动规则：

1. 某联系人 80% 片段完成观察提取后，立即启动该联系人的第一轮关系记忆；
2. 每完成 100 位联系人，就增量更新一次个人记忆和跨关系模式；
3. 每产生一批确认度较高的表达样本，立即进入风格语料队列；
4. 每产生一批事件记忆，立即进入人生故事问答队列；
5. 基础队列始终保留至少 40% worker，直到全量覆盖 100%；
6. 深度分析占约 25% worker，数字分身资产占约 20%，复核和裁判占约 15%；
7. 某队列暂时无任务时，worker 自动领取下一优先级任务，不允许空闲等待。

## 四、多视角分析扩展

在基础观察完整后，对高信息量片段、关键事件和长期关系并行运行六个独立视角。各视角不读取其他视角的结论：

1. **时间线视角**：事件、因果顺序、变化和转折；
2. **关系视角**：主动性、回应、边界、冲突、修复和关系阶段；
3. **沟通视角**：表达结构、倾听、需求、拒绝、邀约和协商；
4. **人生项目视角**：学习、工作、摄影、金融、AIGC、创作和长期目标；
5. **语言风格视角**：词汇、句长、语气、幽默、叙事和解释方式；
6. **怀疑者视角**：主动寻找反例、其他解释和证据不足之处。

随后由证据裁判只根据原文及六个结构化结果生成：

- 一致结论；
- 冲突结论；
- 需要保留的多种解释；
- 应当拒绝的无证据推断；
- 需要本人确认的问题。

## 五、核心结果完成后的自动扩展队列

### A. 多尺度记忆

同一批记忆生成不同用途的版本：

- 单条事实卡；
- 单次事件卡；
- 联系人月度和年度时间线；
- 个人月度和年度人生摘要；
- 按主题整理的长期发展轨迹；
- 事实版、叙事版和问答版三种表达。

这些版本必须共享 `memory_id` 和 `evidence_ids`，不能变成互不相认的重复数据。

### B. 沟通训练集

为有证据支持的真实场景生成：

- 当前表达；
- 保持原意的更清晰表达；
- 更简短版本；
- 更温和版本；
- 更坚定边界版本；
- 适合工作、朋友和亲密关系的不同版本；
- 对方可能产生的三种合理理解；
- 后续追问和关系修复方案；
- 多轮角色扮演脚本；
- 成功信号和复盘问题。

禁止生成操控、欺骗、PUA、冒充或强迫策略。

### C. 数字分身训练与检索资产

持续生成并落盘：

- 个人事实问答；
- 人生故事问答；
- 人物与事件关联问答；
- 观点及观点变化问答；
- 写作与表达风格样本；
- 同一内容的“像本人／不像本人”偏好对；
- 数字分身应当回答“不知道”的负样本；
- 事实冲突和过期记忆测试；
- 多轮长对话一致性测试；
- 防止把他人观点说成本人观点的测试。

每条合成数据标记 `synthetic: true`，并保留生成它的真实记忆和证据 ID。合成内容不得反向写成确认事实。

### D. 对抗与审计资产

自动构建测试集：

- 错误人物归属；
- 错误时间；
- 相似联系人混淆；
- 多个版本的同一事件；
- 诱导数字分身编造；
- 诱导数字分身冒充真人；
- 要求它代表他人表态；
- 要求它把模型推断说成确定事实；
- 长对话中的人格和价值观漂移。

每次测试保存输入、回答、判定、证据和改进建议，形成可供未来模型复用的基准集。

## 六、Token 使用优先级

当剩余额度仍很大时，按以下顺序扩张深度：

1. 全量片段基础观察覆盖率达到 100%；
2. 全部联系人至少有一份证据型长期记忆；
3. 全部人生事件和当前项目进入个人记忆系统；
4. 每个高信息量片段完成六视角分析；
5. 每项重要模式完成独立复核、反证搜索和证据裁判；
6. 生成多尺度记忆、沟通训练集和数字分身问答集；
7. 扩大数字分身对抗测试和偏好对；
8. 对低置信度、冲突和失败项进行更强上下文重跑。

禁止为了追求利用率而对已经稳定、无争议、无新增价值的内容无限重跑。

## 七、进度与自动调度

每 5 分钟更新 `expiry-harvest-status.json`：

```yaml

local_estimated_output_tokens: 0
active_workers: 0
requests_per_minute: 0
tokens_per_minute: 0

queue_depth:
  observations: 0
  relationships: 0
  personal_memory: 0
  coaching: 0
  digital_twin: 0
  verification: 0
coverage:
  segments: 0.0
  contacts: 0.0
  memory: 0.0
disk_free_gb: 0
```

调度器根据数据自动决策：

- 基础覆盖不足时，把更多 worker 调回观察提取；
- 接口稳定但利用率低时提高并发；
- 输出队列阻塞或磁盘空间不足时暂停新调用，先写盘和压缩；
- 账号用量页面可能延迟，必须同时维护本地 Token 估算；
- 到达截止线后不再启动新请求，但必须保存未完成队列以便以后用其他模型继续。
