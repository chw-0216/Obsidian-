# WeFlow 微信聊天记录高效使用方案

> 核心原则：**不要把导出文件当纪念品，也不要整库直接塞给 AI。**
> 一切按四层结构走：**原始档案 → 可检索资料库 → AI 工作区 → 复盘成果**。
> 任何 AI 结论都必须能回溯到：聊天对象/群名、时间、原话。

---

## 0. 总览：一条流水线

```
WeFlow 导出
   │
   ├─ 00_raw        原始档案（只读、加密备份、绝不修改）
   │
   └─ ChatLab 本地库  ← 全文检索，把"翻手机找旧话"变成秒级搜索
         │
         └─ 按需抽取相关片段（只在需要时取一小段）
               │
               ├─ 私密内容 → Ollama 本地模型（hermes3:8b，不联网）
               ├─ 非敏感/脱敏后 → 云端模型（能力更强）
               │
               └─ 03_reviews    复盘成果：项目、人物、灵感、报价
```

为什么这样分层：
- **效率**：检索走本地索引，AI 只看相关片段（几百字），不看整库（几万条），既快又省 token；
- **隐私**：原始数据从不出本机，云端只接触脱敏片段；
- **可维护**：原始档案只读，后续任何整理、分析失败都能重来，不会污染源数据。

---

## 1. 第一步：导出与原始档案（00_raw）

### 1.1 导出设置建议
- **增量导出**：先做一次全量，之后定期增量拉取（WeFlow 支持本地 API / 增量拉取，若你的版本可用则优先走 API，见 2.1）；
- **按时间分批**：建议按年（数据大可按月）建子目录，避免单文件过大；
- **保留完整字段**：时间戳、发送人、群名、消息类型（文本/图片/语音转文字/文件）都要留，后续检索全靠它们。

### 1.2 目录结构（照抄即可）

```
D:\ChatArchive\
├── 00_raw\            ← 原始导出，只读，任何程序都不改写这里
│   ├── 2023\
│   ├── 2024\
│   └── 2025\
├── 01_index\          ← ChatLab 资料库（从 00_raw 导入或 API 同步）
├── 02_ai_workspace\   ← 临时抽取、脱敏后的待分析片段
└── 03_reviews\        ← 复盘成果（项目/人物/灵感/报价）
```

### 1.3 备份规则（3-2-1）
- **3** 份：电脑本机 + 移动硬盘 + 加密网盘/另一台设备；
- **2** 种介质：至少两种不同存储介质；
- **1** 份异地：防火灾/丢失/勒索软件。
- 原始导出文件用 **hash（SHA-256）去重**：增量导出时先比对已有文件的 hash 和时间戳，避免重复导入、重复分析。

## 2. 第二步：ChatLab 本地检索库（01_index）

把聊天变成"可搜索的资料库"，这是全方案效率的关键。

### 2.1 两种接入方式（二选一）
1. **WeFlow 本地 API 增量拉取（优先）**：如果你的 WeFlow 版本支持面向 ChatLab 的本地 API，直接接通，之后每次打开都能增量同步，最省事。
2. **通用文件导入（兜底）**：把 WeFlow 导出为 TXT / JSON / Markdown 后批量导入 ChatLab。文件名里保留日期与对象，例如 `2024-11_某项目群.txt`。

### 2.2 检索习惯（养成后收益最大）
- 先**过滤范围**（人 / 群 / 时间区间），再输关键词，速度比全库模糊搜索快一个量级；
- 关键词用**原话特征词**（对方爱用的词、项目代号、地名），不要用自己脑内转述后的词；
- 常用问题固化下来，例如：
  - "某项目群里提到过的所有**截止日期**"
  - "我和 X 最后一次聊 Y 话题是什么时候、结论是什么"
  - "去年所有关于**报价**的消息"

### 2.3 为什么不全库塞给 AI
一个几百 MB 的聊天库，AI 一次读不完、读完也会"稀释重点"、还会把不相关内容混进回答。正确做法永远是：**先用 ChatLab 检索出 3~10 条相关原话片段，只把片段交给 AI。** 这叫"检索增强分析"，速度快、答案准、还便宜。

---

## 3. 第三步：AI 分析流水线（02_ai_workspace）

### 3.1 模型分工（隐私边界，照此执行）

| 内容类型 | 用哪个模型 | 理由 |
|---|---|---|
| 私人对话、家庭、敏感讨论 | Ollama 本地 hermes3:8b | 全程不联网，数据不出本机 |
| 工作/公开/技术讨论 | 本地优先；量大或要深度可上云端 | 平衡能力与隐私 |
| 任何要外发的片段 | 云端模型 | 必须先**脱敏**（见 3.2） |

### 3.2 脱敏规则（外发给云端前必做）
- 姓名 → `[人名1]`、`[人名2]`（保持对应关系不变）
- 手机号/微信号 → `[联系方式]`
- 地址/身份证/银行卡 → `[地址]`/`[证件]`/`[卡号]`
- 金额、报价 → 可保留（分析报价往往需要），但结合语境判断
- 只发**当前问题所需的最少片段**，不发整段历史

### 3.3 提示词模板（可复制）

```
你是一名聊天记录分析助手。以下是来自聊天记录的几个片段。
请只依据这些片段回答，不要补充片段中没有的信息。
要求：
1. 完成这个任务：______（如：列出所有待办事项及提出人和时间）
2. 每条结论后标注来源（片段编号 + 时间）
3. 片段中没有答案就直接说"片段中未提及"
4. 区分"事实"与"你的推测"

片段如下：
[片段1] 2024-11-02 张三：……
[片段2] 2024-11-05 李四：……
```

## 4. 第四步：定期复盘输出（03_reviews）

每周固定 30 分钟，或每月一次批量，产出四类成果：

1. **项目复盘**：待办事项、已做决策及背景、未完成事项、下次约定 → `03_reviews/项目复盘/`
2. **关系复盘**：重要联系人、最近联系时间、对方提过的需求或承诺 → `03_reviews/人物/`
3. **创意与素材**：灵感、金句、好链接、可用模板 → `03_reviews/灵感素材/`
4. **报价与线索**：历史报价、客户反馈、跟进状态 → `03_reviews/报价线索/`

每条复盘结论都带"来源链接"（聊天对象 + 时间 + 原话），做到可追溯。

## 5. 落地清单（按顺序执行）

- [ ] 1. 确认你的 WeFlow 版本与导出格式（是否支持本地 API / 增量导出）
- [ ] 2. 创建 `D:\ChatArchive` 目录结构（见 1.2）
- [ ] 3. 做第一次全量导出到 `00_raw`，SHA-256 去重
- [ ] 4. 立即备份一份到移动硬盘/加密网盘
- [ ] 5. 打开 ChatLab，导入或接通 WeFlow API，建立索引
- [ ] 6. 测试检索：找一句"你记得说过但记不清原话"的话，验证秒级命中
- [ ] 7. 用 Ollama 跑一次样例分析（挑一个群的一周记录，提取待办）
- [ ] 8. 按第 4 节建复盘模板，跑第一次周复盘

---

## 6. 明确不做的事

- ❌ 不拿聊天记录训练"人设模型"——聊天气质无法可靠还原，且隐私风险大；
- ❌ 不整库上传任何云端 AI；
- ❌ 不修改、不删除 `00_raw` 里的任何原始文件；
- ❌ 不在多台设备上各自维护一份"整理版"——只认 `00_raw` 一个源头，其余全部可重建。

## 8. 立即执行（步骤与出处均已核实）

### 8.0 先确认你的 WeFlow 导出能力（1 分钟）
打开手机上的 WeFlow 应用，看"设置 / 导出"页面里有哪些选项。WeFlow 的标准能力：
- **HTTP API 推送**：直接推送给同一局域网里的 ChatLab（这是最省事的方式，[WeFlow HTTP API 文档](https://github.com/lurve1314/WeFlow/blob/main/docs/HTTP-API.md)）；
- 本地导出/年度报告：导出的数据一般以**本地数据库 / 结构化文件**为主。
如果页面上有"API 推送 / 推送到 ChatLab"选项，说明你的版本支持，走 8.2；否则走 8.3（导出文件再导入）。完整教程可参考 [WeFlow 安装与使用教程](https://blog.ybyq.wang/archives/1492.html/)。

### 8.1 安装 ChatLab（电脑端，5 分钟）
1. 打开 [ChatLab Releases 页面](https://github.com/ChatLab/ChatLab/releases)，下载最新版（v0.36.0+）的 **Windows 安装包**；
2. 安装后先**不要导入任何数据**，等 8.2/8.3 配好再说；
3. 官方文档：[快速开始](https://docs.chatlab.fun/cn/usage/quick-start)、[导入聊天记录指南](https://docs.chatlab.fun/cn/usage/how-to-import)。

### 8.2 方式 A：WeFlow API 推送（版本支持时首选）
1. 手机与电脑连**同一 Wi-Fi**；
2. 电脑端 ChatLab 打开"API 推送"入口，记下它给的地址（`http://电脑IP:端口`）；
3. 手机 WeFlow 设置里填入该地址，选择要推送的聊天/时间段（**按年分批推**，5GB 数据别一次全推）；
4. 推送完成后在 ChatLab 里验证能搜到原话，再推下一批。

### 8.3 方式 B：导出文件导入（兜底）
1. WeFlow 导出为文件（优先 JSON / 数据库，其次 TXT），按年存到 `D:\ChatArchive\00_raw\2024\` 等目录；
2. 用 SHA-256 去重后再导入 ChatLab；
3. ChatLab 支持常见格式导入，具体见[导入指南](https://docs.chatlab.fun/cn/usage/how-to-import)。

### 8.4 接上 Ollama（私密分析）
ChatLab 设置 → 模型服务 → 选择 Ollama，指向本机 `http://127.0.0.1:11434`，选 `hermes3:8b`。之后所有"只在本机"的分析任务都走它，云端模型只处理脱敏片段（见第 3 节）。

### 8.5 我可以代劳的部分
- 编写导出后的**去重脚本**（SHA-256）、**目录整理脚本**；
- 生成各用途的**复盘提示词模板**（项目/人物/灵感/报价）与每周复盘清单；
- ChatLab 装好后，帮你核对 API 推送配置、指导第一次分批导入。

## 10. 数字人个人资料库（扩展层）

> 定位：**可回溯的档案数字人**，不是"复刻人格"。
> 聊天记录只能反映"聊天中的你"，所以资料库是一份带出处的快照档案，数字人的一切回答都从档案里来、都能指回原话。
> 施工模板（时间线模板、抽取提示词、"关于我"文件、风格卡与陪伴对话提示词）见配套文档：《数字人个人资料库-建设手册.md》。

### 10.1 它在流水线里的位置

```
00_raw → 01_index（ChatLab 检索）
              │
              └→ 每周复盘抽取候选事实（Ollama 本地）
                       │
                       ├─ 你人工确认后 → 02_profile（数字人资料库，核心资产）
                       └─ 临时片段 → 02_ai_workspace（用完即弃）
                                    │
                                    └→ 数字人问答 = 检索资料卡 → 组织回答 → 标注来源
```

### 10.2 资料卡 Schema（8 类，建议 JSON / Markdown 卡片）

| # | 卡片类型 | 内容示例 | 敏感度 |
|---|---|---|---|
| 1 | 基本档案 | 身份、职业、常驻地 | 部分字段加密 |
| 2 | 经历时间线 | 事件、项目、成就 + 时间 + 出处 | 低～中 |
| 3 | 关系图谱 | 人物、关系类型、亲密度、最近互动 | 中 |
| 4 | 偏好与习惯 | 饮食、作息、爱好、常用语、口头禅 | 低 |
| 5 | 观点与价值观 | 对事物的态度（注明讨论场景） | 中 |
| 6 | 承诺与待办 | 对谁承诺过什么、是否兑现 | 中 |
| 7 | 语言风格档案 | 词频、句长、表情使用率、常用开头结尾（**纯统计**） | 低 |
| 8 | 知识与兴趣域 | 常讨论话题的聚类 | 低 |

一张事实卡的格式（每条都能回溯）：

```json
{
  "id": "fact-2024-1103-01",
  "type": "偏好与习惯",
  "fact": "偏好早睡早起，工作日约 23:00 前休息",
  "confidence": "明确陈述",
  "source": { "chat": "家人群", "date": "2024-11-03", "quote": "原话片段" },
  "confirmed_by_user": true
}
```

### 10.3 构建流程（复用第 4 节周复盘，零额外习惯成本）

1. **抽取**：周复盘时用 Ollama 对检索出的片段跑"候选事实抽取"（提示词模板见下）；
2. **确认**：你逐条点头才入库——数字人只收录你认可的内容，这是它可信的关键；
3. **分级**：敏感字段分三级存储——A 级本机明文、B 级加密、**永不入库**（密码、银行卡、验证码）；
4. **回写**：每张卡带 `source`，任何数字人回答都能跳回聊天名 + 时间 + 原话。

候选事实抽取提示词（Ollama 本地跑）：

```
你是档案整理员。从以下聊天片段中抽取关于【目标人物】的候选事实。
规则：
1. 只抽取明确陈述，不推断
2. 每条包含：事实内容、卡片类型（经历/偏好/观点/承诺/关系）、置信度（明确陈述/间接提及）
3. 逐条标注片段编号与时间
4. 不确定的宁可不抽
片段：……
```

### 10.4 数字人的运行方式（RAG 问答，全程本地）

- **问答链路**：问题 → 检索 02_profile 相关卡片 → 用设定口吻组织 → 回答末尾附引用列表；
- **风格层（可选）**：把第 7 类"语言风格档案"变成提示词修饰（"常用短句、爱用 X 表情"），并在对话中**明示这是统计模拟**，不冒充本人；
- **技术栈**：Ollama（hermes3:8b）+ 本地向量检索或全文检索，不联网；
- **诚实声明**：回答必须区分"记录中的事实 / 基于记录的推测 / 无记录"，无记录就说不知道。

### 10.5 边界（照此执行）

- 数字人不知道聊天记录之外的事，不编造没说过的话；
- 若资料库涉及**他人**（如梳理某位亲友的生平），使用与展示前需对方知情同意；
- 风格模拟只用于"像你的表达方式"，不用于代替你对外承诺、回复或签署任何东西。
