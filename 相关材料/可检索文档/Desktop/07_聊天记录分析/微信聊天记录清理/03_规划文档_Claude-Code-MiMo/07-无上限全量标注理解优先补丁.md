# 微信数据：无上限全量标注理解优先补丁

> 最高优先级补丁。目标是先让 MiMo 尽可能完整地“看懂并标注全部数据”，暂缓过早总结、关系裁决和数字分身生成。本文编号最高，与 `04`—`06` 冲突时以本文为准。

## 一、当前唯一首要目标

在 Token Plan 到期前，对全部微信私聊进行**无人工预算上限的穷尽式、多轮、可追溯标注**：

- 不因为消息短、人物不重要或关系不活跃而跳过；
- 不只标注高信息量片段；
- 不只抽样关键联系人；
- 不提前用联系人摘要替代原文理解；
- 不设置项目内部 Token 软上限或单联系人预算；
- 在实际账号额度、到期时间、接口限流和磁盘容量允许范围内持续运行；
- 标注结果全部落盘，后续模型无需重新读取所有原文即可继续分析。

第一阶段先建立完整“语义证据层”，不急着输出谁好谁坏、关系值不值得、人格是什么。

## 二、完成门槛

标注阶段必须达到：

```yaml
message_coverage: 1.00
segment_coverage: 1.00
contact_coverage: 1.00
evidence_link_rate: 1.00
parse_failure_rate: 0.00
unresolved_model_failures: 0
schema_validation_rate: 1.00
```

已知目标规模：

- 725 个有效私聊；
- 71,550 条消息；
- 6,303 个对话片段。

如果到期前无法达到 100%，必须优先覆盖更多尚未标注的消息，而不是重复深挖少数联系人，并保存精确未完成队列。

## 三、六轮穷尽标注

### Pass A：原子消息标注

每条消息都产生一个 annotation，包括低信息消息、表情、撤回提示、媒体占位和系统提示。

字段至少包括：

```yaml
message_id: 稳定消息 ID
segment_id: 所属片段
contact_id: 稳定联系人 ID
sender: self | contact | system
timestamp: 原始时间
message_type: text | image | voice | video | file | link | emoji | system | other
content_role: substantive | acknowledgement | backchannel | greeting | transition | noise
language: 语言或混合语言
reply_to: 被回应消息 ID 或 null
explicit_entities: []
explicit_time_references: []
explicit_locations: []
explicit_people: []
explicit_events: []
explicit_requests: []
explicit_commitments: []
explicit_preferences: []
explicit_boundaries: []
speech_acts: []
intents: []
topics: []
observed_tone: []
inferred_emotion_hypotheses: []
relationship_signals: []
communication_behaviors: []
style_features: []
memory_candidates: []
ambiguities: []
confidence: 0-1
evidence_text_span: []
model_version: null
prompt_version: null
```

一条消息允许多标签，不强制只能选一个主题、意图或情绪。

### Pass B：对话上下文标注

逐片段读取完整上下文，修正孤立消息容易产生的误读：

- 当前对话由什么触发；
- 真实讨论目标；
- 主题如何转移；
- 谁在回答谁；
- 省略的主语和指代对象；
- 玩笑、反讽、引用、转述和口误；
- 对话中的请求—回应—结果链；
- 情绪和语气转折；
- 是否形成决定、承诺、冲突、修复或未完成事项；
- 哪些消息只有结合前后文才有意义。

Pass B 可以修改 Pass A 的推断标签，但必须保留修改历史。

### Pass C：跨片段实体与事件合并

在同一联系人和相邻时间范围内处理：

- 同一个人、地点、项目、作品、活动的不同称呼；
- 备注名变化；
- 同一事件在多次聊天中的预告、发生、复盘和后续；
- 同一承诺的提出、延期、完成、取消；
- 同一冲突的起因、发展、冷却和修复；
- 指代不明、时间模糊和多个候选实体。

输出实体解析表、事件链和无法确定的候选列表，不强制错误合并。

### Pass D：语义深描

对每个片段从多个维度独立标注：

1. **内容层**：谈了什么；
2. **行动层**：谁希望谁做什么；
3. **关系层**：互动中出现了什么亲近、疏离、试探、边界或修复信号；
4. **情绪层**：直接表达和可推断情绪分别是什么；
5. **需求层**：可能涉及理解、认可、连接、自主、安全、效率、支持或公平；
6. **身份层**：本人如何描述自己的角色、经历和价值；
7. **风格层**：表达结构、词汇、句长、幽默、解释和叙事方式；
8. **记忆层**：哪些信息值得进入长期记忆，为什么；
9. **不确定性层**：哪些地方无法判断、有哪些替代解释。

语义深描只产生候选观察和假设，不在此阶段做最终人格或关系裁决。

### Pass E：独立复标与分歧裁判

每个高信息量片段至少执行：

1. 第一标注器；
2. 不读取第一结果的独立第二标注器；
3. 分歧比较器；
4. 读取原文的证据裁判。

普通低信息量片段如两轮结果一致，可不启动裁判；出现以下情况必须裁判：

- 人物或事件归属不同；
- 请求、承诺或边界判断不同；
- 情绪和关系信号差异明显；
- 置信度低于 0.7；
- 涉及关键人生事件；
- 将来可能进入深层判断或数字分身。

### Pass F：全局一致性回扫

全部联系人基础标注结束后，全库检查：

- 同一人物是否被拆成多个实体；
- 两个同名联系人是否被错误合并；
- 同一事件时间是否冲突；
- 相同承诺是否出现不同状态；
- 早期偏好是否已经变化；
- 他人的观点是否被错误归到本人；
- 引用、转发和转述是否被当作本人表达；
- 同一种表达在不同关系中是否含义不同；
- 是否存在尚未关联的跨对话事件。

## 四、穷尽标签体系

### 1. 内容主题

工作、学习、金融、摄影、AIGC、数字媒体艺术、创作、家庭、朋友、情感、健康、消费、旅行、居住、设备、软件、娱乐、新闻、人生规划等；允许自动发现新主题。

### 2. 言语行为

询问、回答、请求、命令、建议、邀请、确认、拒绝、解释、澄清、承诺、提醒、汇报、分享、安慰、赞美、感谢、道歉、抱怨、质疑、协商、玩笑、试探、结束话题、转移话题。

### 3. 互动行为

主动发起、跟进、回应、追问、复述理解、自我披露、情绪承接、提供方案、提供资源、给出边界、让步、回避、延迟回应、忽略问题、关系修复、共同决策。

### 4. 事件与行动

会面、计划、决定、承诺、截止、完成、延期、取消、冲突、修复、合作、付款、借还、作品、旅行、搬迁、求职、学习、购买、健康事件和人生转折。

### 5. 关系信号

亲近、信任、自我披露、依赖、支持、互惠、邀约、共同回忆、边界、试探、冷淡、疏离、冲突、道歉、修复、功能性交往、关系降温和重新连接。

这些只是聊天行为信号，不直接等于真实关系结论。

### 6. 情绪与需求

明确情绪和推断情绪分开；可能需求包括理解、认可、归属、陪伴、自主、确定、安全、尊重、公平、效率、成长、掌控、休息和表达。

### 7. 风格特征

简短／详细、直接／铺垫、正式／口语、理性分析、情绪表达、幽默、自嘲、比喻、故事化、列表化、连续补充、语气词、表情使用、标点习惯和代码切换。

### 8. 记忆候选

稳定事实、人生事件、关系事件、观点、偏好、价值观、项目状态、承诺、经验教训、表达样本、矛盾信息、可能过期信息。

## 五、模型不得偷懒的规则

1. 不得用“内容较少，无需分析”跳过消息；低信息量也是互动节奏证据。
2. 不得把几十条消息压成一句摘要后丢失请求、承诺和转折。
3. 不得只输出预设标签；发现新概念时写入 `emergent_labels`。
4. 不确定时列出候选解释，不强迫选择。
5. 每个标签必须指向具体消息或文字片段，不能只凭整体印象。
6. 联系人摘要不能覆盖或替代消息级、片段级标注。
7. 后续模型可以修正标签，但不得静默覆盖历史版本。
8. 任何调用失败、截断、空响应或 Schema 不合格都必须进入重试队列。

## 六、无上限的实际定义

```yaml
internal_token_soft_limit: null
per_contact_token_limit: null
per_segment_pass_limit: null
skip_low_information_messages: false
sample_contacts_only: false
high_information_only: false
stop_when_summary_exists: false
continue_until_provider_stops_or_deadline: true
```

“无上限”不代表无意义重复。同一输入、同一提示词、同一模型版本已有合格结果时不重复运行。额外 Token 用于：

- 不同视角；
- 上下文修正；
- 独立复标；
- 分歧裁判；
- 跨片段实体和事件合并；
- 全局一致性回扫；
- 低置信度重分析。

## 八、标注完成前的冻结规则

在以下条件达成前，禁止把主要算力转去生成最终关系结论、沟通建议或数字分身：

1. 全部消息至少完成 Pass A；
2. 全部片段至少完成 Pass B；
3. 所有高信息量和关键事件片段完成 Pass D；
4. 低置信度及分歧项已经进入裁判或明确未解决；
5. 标注结果通过 Schema 和证据回链检查；
6. `ANNOTATION-COVERAGE.md` 明确记录实际覆盖率。

为了不浪费并发，可以在标注流水线已经覆盖 80% 后，用不超过 20% worker 增量试运行联系人记忆；但深层判断和数字分身不得抢占标注主队列。

## 十、标注之后才进入的阶段

标注覆盖门达成后，按以下顺序消费标注资产：

1. 个人记忆系统；
2. 联系人关系时间线；
3. 最激进分析判断；
4. 沟通改善与行为实验；
5. 数字分身和训练语料；
6. 事实审计与长期增量更新。

这样即使 Token Plan 到期，最宝贵的“模型对全部原始聊天的细粒度理解”已经被保存下来，后续任何模型都可以继续使用。
