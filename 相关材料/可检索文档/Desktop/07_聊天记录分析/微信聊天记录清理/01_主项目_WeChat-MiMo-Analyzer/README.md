# WeChat MiMo Analyzer

这是一套面向 WeFlow 私聊详细 JSON 的本地分析框架。它先在电脑上完成清洗、分段、统计和全文索引，再通过现有 Claude Code 配置调用小米 MiMo Token Plan，生成可追溯的结构化标注。

- 有有效详细 JSON 的私聊：725 个；其余 2300 个目录为空。
- 已读取消息：71,550 条，725 个 JSON 全部有效。
- 时间范围：2024-11-10 至 2026-07-24。
- 对话片段：6,303 个。
- 本地 SQLite/FTS5 全文索引：71,550 条。
- MiMo 试运行：3 个片段，严格结构化输出成功。

目录数量不代表有内容的对话数量；当前可读导出也不代表旧版原始备份中的所有历史都已被解析。

## 分析框架

1. **消息层**：保留原文，同时生成不破坏语气和表情的清理文本。
2. **片段层**：默认按 90 分钟间隔、60 条消息或 10,000 字符切分，避免把多年对话一次性塞给模型。
3. **MiMo 标注层**：输出摘要、主题、互动类型、可观察语气、关键事件、待办、关系迹象、重要度、隐私等级、置信度和证据消息 ID。
4. **汇总层**：按月份、联系人、主题、待办和高重要度片段生成本地报告。
5. **检索层**：原文关键词用 SQLite FTS5；MiMo 主题与摘要使用标注搜索。

MiMo 默认看到匿名联系人编号；发送前会替换常见手机号、邮箱、身份证号、银行卡号和 IP。聊天正文仍可能含有规则无法识别的隐私，批量分析意味着相关片段会发送给 MiMo 接口。

## 推荐使用顺序

在本项目目录打开 PowerShell：

```powershell
# 1. WeFlow 导出发生变化时，重新建立本地索引
.\run.ps1 -Action ingest

# 2. 先标注 3 个片段并生成报告
.\run.ps1 -Action pilot

# 3. 每次处理 10 批高信息量片段，自动保存进度
.\run.ps1 -Action analyze -LimitBatches 10

# 4. 重新生成报告
.\run.ps1 -Action report

# 5. 核验数据库、标注结构和证据 ID
.\run.ps1 -Action verify

# 6. 搜索原始消息
.\run.ps1 -Action search -Query "摄影" -SearchLimit 20

# 7. 搜索 MiMo 主题和摘要
.\run.ps1 -Action search-labels -Query "工作协作"
```

`analyze` 默认只选择至少 5 条消息、500 字符且双方都有发言的高信息量片段，并设置单次运行的用量保护线。已完成片段不会重复标注；源片段变化后旧标注自动失效。

## 三阶段分析建议

### 第一阶段：全量本地画像

不调用 MiMo，先看消息量、联系人活跃度、月度变化、发送/接收比例和时间分布。这一步覆盖全部 71,550 条消息。

### 第二阶段：高信息量语义标注

按小批次运行 `analyze`，优先处理双向、较长、包含事件和任务的对话。先检查报告中的标签质量，再逐步扩大覆盖，避免无差别处理“好的”“谢谢”等低价值记录。

### 第三阶段：专题深度理解

围绕明确问题筛选证据后再让 MiMo 汇总，例如：

- 过去一年重要人际关系如何变化？
- 哪些承诺和待办尚未完成？
- 学业、工作、摄影和创作主题分别经历了什么阶段？
- 哪些联系长期单向，哪些互动稳定且双向？
- 自己在冲突、求助、拒绝和关系修复中的表达模式是什么？

深度结论必须附带联系人、时间、片段 ID 或证据消息 ID；不能把模型推测当作事实。

## 文件说明

- `data\wechat-private-v2.sqlite3`：当前本地索引和标注数据库。
- `reports\overview.md`：可读汇总报告。
- `reports\overview.json`：机器可读报告。
- `config\analysis.schema.json`：MiMo 输出结构。
- `src\weflow_ingest.py`：导入、清洗、分段和索引。
- `src\analyze_with_claude.py`：Claude Code + MiMo 批量标注。
- `src\build_report.py`：报告生成。
- `src\search.py`：消息和标签搜索。
- `src\verify.py`：数据库、标注结构和证据链核验。

`data\obsolete\` 中仅保存首次调试生成的不完整派生索引，可在确认当前数据库稳定后删除；它不属于微信原始数据。
