## 五、本次实现的风险与边界

- **不是官方 UI 改名**：DSH 0.2.x 没有批量改名接口；本次是“日志追加 + 投影缓存补丁”。操作时服务已停止，写入后有逐条校验。
- **标题事件是 `source.kind = "user"`**：这会永久抑制该会话的自动标题生成，所以以后新消息不会把名字改回去；反过来说，会话用途变了也不会自动更新，需要手动再改。
- **缓存版本为 7**：如果 DSH 升级后重建缓存，标题会从日志重新折叠，新名仍在；如果缓存结构变了，可能需要重跑补丁脚本（已备份在 `state\backups\dsh-patch-projcache-20261023.js`）。
- **未删除任何会话、未改任何消息**：回滚依据是各 manifest 的 `sizeBefore`；不要在没有清单的情况下截断日志。
- **凭据只在标题层被覆盖**：日志正文与旧标题事件仍保留原文；这是 P0 第 3 条要处理的原因。
