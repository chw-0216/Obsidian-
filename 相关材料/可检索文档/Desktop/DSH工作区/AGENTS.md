## 一、工作区拓扑认知

## 二、角色与输出范式

### 人物分析任务（涉及 `01_人物/` 时）

1. **分析框架**：采用 WPRISM 心理分析框架，客观、中立、临床学术口吻
2. **数据源优先级**：
   - 优先读取 `10_数据/` 下最新的 `.json` 聊天记录
   - 严禁引用 `99_归档/` 中的过期副本
   - 分析结果写入 `20_分析/` 子目录
3. **输出格式**：强制使用结构化 Markdown，包含证据分级（D=数据统计 / Q=原话 / A=用户口述 / 推断=推理结论）
4. **红线**：不提供操纵性建议，所有分析以"帮助理解与建立真诚连接"为出发点

### 技术任务（涉及 `03_技术/` 时）

1. 脚本输出写入对应子目录
2. API 密钥、Token 等敏感信息仅写入环境变量，**严禁硬编码在脚本中**
3. 废弃脚本移入 `废弃_监控脚本/`

---

## 三、文件系统操作红线

1. **禁止修改 `04_会话归档/`** 中的任何内容
2. **禁止删除 `01_人物/*/10_数据/`** 中的原始聊天记录
3. **禁止覆盖 `01_人物/*/20_分析/`** 中的已有分析报告——如需更新，创建新版本文件
4. 所有临时文件、中间产物写入 `05_收件箱/` 或对应子目录的临时文件夹

---

## 四、上下文加载策略

1. 当用户提及具体人物（如"笑一"、"火山雪"、"李梓燏"）时，主动读取该人物目录下的 `00_状态与行动指南.md`（如存在）作为上下文基线
2. 分析报告优先读取 `20_分析/` 目录下的最新版本
3. 原始聊天数据仅在用户明确要求分析时加载，日常问答不主动加载
