## 0. 一句话结论

**这段代码是给「无源蜂鸣器」写的。** 如果你手上的是有源蜂鸣器，它能响，但**放不出《遇见》**——只会变成一串音高完全相同的"滴滴滴滴"。

另外，代码里有一处**数组越界**，导致后半段 97 个音符会被瞬间跳过（编译器自己都会报警）。

## 1. 最重要的事：你的蜂鸣器是有源还是无源

这是决定这段代码能不能用的关键。

### 两者的本质区别

| | 有源蜂鸣器（Active） | 无源蜂鸣器（Passive） |
|---|---|---|
| 内部结构 | **自带振荡电路**，通电就自己振 | 只有压电片/线圈，**没有振荡电路** |
| 怎么让它响 | 给电就响 | 必须给它**方波信号** |
| 音高由谁决定 | 内部电路固定（通常 2~4 kHz） | **由你给它的方波频率决定** |
| 能不能演奏旋律 | ❌ 不能，永远一个音 | ✅ 能，改频率就是改音高 |
| 常见外观 | 黑色密封圆柱，背面有电路 | 能看到黄铜片/陶瓷片 |
| 价格 | 稍贵一点 | 便宜（几毛钱） |

### 为什么有源蜂鸣器放不出歌

代码里核心的一句是：

```cpp
tone(tonePin, tune[x]);   // 给蜂鸣器一个特定频率的方波
```

`tone()` 做的事情是**让引脚输出指定频率的方波**。

- 接**无源**蜂鸣器：方波直接驱动压电片振动，频率 262Hz 就是中央 C，频率 441Hz 就是 A —— **每个音符音高不同，于是成了旋律**。
- 接**有源**蜂鸣器：它内部的振荡电路无视你的方波频率，只把方波当成"通电/断电"的开关。你给它 262Hz，它用自己固定的 2300Hz 响一下；给它 441Hz，它还是用 2300Hz 响一下。**结果就是音高全一样，只剩节奏。**

### 三秒钟判断手上的型号

1. **直接接 5V 和 GND**（不要经过 Arduino）
   - 持续发出稳定的响声 → **有源**
   - 只"嗒"地响一下（或只有轻微的咔哒声）→ **无源**
2. **看背面**：有黑色环氧树脂封装、底下明显有电路板 → 有源；能直接看到黄铜圆片 → 无源
3. **看商品标签**：写"5V 有源蜂鸣器"就是有源；写"无源"、"蜂鸣片"、"piezo"就是无源

### 结论

- **想放出《遇见》** → 必须换一颗**无源蜂鸣器**（几毛钱一个）
- **只有有源蜂鸣器** → 这段代码只能当"节奏器"用，音高不变；或者改成 `digitalWrite` 开开关关，做简单的"滴滴"提示音

## 2. 这段代码在做什么

它用两个**平行数组**来描述一首曲子：

```
tune[]      —— 每个音符的频率（唱什么）
duration[]  —— 每个音符的时长（唱多久）
```

两个数组**下标一一对应**：`tune[0]` 配上 `duration[0]` 就是第一个音，依此类推。

播放时就是一个循环：

```
对每个音符:
    用 tone() 发出对应频率
    按节拍等待
    用 noTone() 停掉
```

### 实测统计出来的曲子信息

| 项目 | 数值 |
|---|---|
| 音符总数 | **245 个** |
| 其中休止符（`NOTE_C0 = -1`） | 30 个 |
| 实际发声 | 215 个 |
| 最低音 | 221 Hz（A3） |
| 最高音 | 882 Hz（A5） |
| 音域跨度 | 661 Hz（约两个八度） |
| 节拍数组长度 | **148 个** ← 少了 97 个，见问题 1 |

## 3. 逐段解读

### 3.1 音符频率表（第 1~27 行）

```cpp
#define NOTE_C0   -1      // 休止符（不发声）
#define NOTE_CL1 131      // 低八度 C
...
#define NOTE_C1 262       // 中央 C
...
#define NOTE_CH1 525      // 高八度 C
```

命名规则：

- `CL` = C Low（低八度），`C` = 中音，`CH` = C High（高八度）
- 数字 1~7 对应简谱的 do re mi fa sol la si
- 这些频率值采用的是**十二平均律**，和标准音高基本吻合

对照表（部分）：

| 宏 | 频率 | 实际音名 |
|---|---|---|
| `NOTE_C1` | 262 | C4（中央 C） |
| `NOTE_C4` | 350 | F4 |
| `NOTE_C7` | 495 | B4 |
| `NOTE_CH1` | 525 | C5 |

**关于休止符 `-1`**：这个写法能"凑巧"工作——`-1` 传给 `tone()` 时会变成无符号数 65535，算出约 **65.5 kHz 的超声波**，超出人耳范围，所以你听不见。但这属于依赖巧合，更干净的写法是判断后直接跳过（修正版就是这么做的）。

### 3.2 节拍定义（第 31~35 行）

```cpp
#define WHOLE 1
#define HALF 0.5
#define QUARTER 0.25
#define EIGHTH 0.25       // ← 错，应该是 0.125
#define SIXTEENTH 0.625   // ← 错得离谱，应该是 0.0625
```

这几行**有两个错误**：

1. `EIGHTH`（八分音符）应该是 `0.125`，写成了 `0.25`，和 `QUARTER` 撞了
2. `SIXTEENTH`（十六分音符）应该是 `0.0625`，写成 `0.625`，大了 **10 倍**

不过好在——**这五个宏从头到尾一次都没被用到**。`duration[]` 里全是字面量数字。所以是纯废代码，不影响运行，但会误导读代码的人。

### 3.3 tune[] 音符序列（第 38~81 行）

245 个音符，每行末尾都有中文歌词注释，说明对应的字：

```cpp
NOTE_C0,NOTE_C0,NOTE_C0,NOTE_C5,NOTE_C3,     // 听见
```

这是**简谱转代码**的典型产物：作者先把旋律转成音名，再映射成频率。

### 3.4 duration[] 节拍序列（第 83~123 行）

```cpp
1,1,1,0.5+0.5,     // 听见
1,0.5+0.5,1,0.5+0.5,   // 冬天的离
```

写法很有意思：`0.5+0.5` 表示"两个半拍"，作者用加法来标注节奏分组。

**但是**——实测发现，所有这些表达式算出来**全都是 1.0**：

| 写法 | 出现次数 | 实际值 |
|---|---|---|
| `0.5+0.5` | 93 | 1.0 拍 |
| `1` | 54 | 1 拍 |
| `0.25+0.25+0.25+0.25` | 1 | 1.0 拍 |
| **合计** | **148** | **全是 1 拍** |

也就是说，**这个数组里没有任何节奏变化**，每个音符都是等长的 1 拍（400ms）。原本的歌词分组注释是有意义的信息，但节拍数值全被写成了 1。

### 3.5 setup()（第 130~138 行）

```cpp
pinMode(tonePin, OUTPUT);
length = sizeof(tune) / sizeof(tune[0]);
```

`sizeof(tune) / sizeof(tune[0])` 是 C/C++ 里**求数组元素个数**的经典写法：

- `sizeof(tune)` = 整个数组占的字节数 = 245 × 2 = 490
- `sizeof(tune[0])` = 单个元素的字节数 = 2
- 相除 = 245 ✓

这个写法本身很聪明，**数组变长了不用改代码**。但它只算了 `tune` 的长度，**没有检查 `duration` 的长度**——这就是问题 1 的根源。

### 3.6 loop()（第 140~154 行）

```cpp
for (int x = 0; x < length; x++) {
    tone(tonePin, tune[x]);
    delay(400 * duration[x]);
    noTone(tonePin);
}
delay(5000);
```

逐句：

| 代码 | 作用 |
|---|---|
| `for (x = 0; x < length; x++)` | 遍历全部 245 个音符 |
| `tone(tonePin, tune[x])` | 让 D7 输出对应频率的方波，开始发声 |
| `delay(400 * duration[x])` | 保持这个音 400ms × 节拍数 |
| `noTone(tonePin)` | 停止发声，准备下一个音 |
| `delay(5000)` | 整首放完停 5 秒，从头再来 |

**注意 `delay()` 的代价**：这 400ms 里单片机**完全被卡住**，什么也干不了。所以用这份代码时，别指望它同时读传感器或控制别的灯。

## 4. 实测发现的 5 个问题

### 问题 1（严重）：两个数组长度不匹配，读到数组外面去了

**实测数据：**

```
tune[]      :  245 个音符
duration[]  :  148 个节拍
→ 差 97 个
```

`for` 循环按 `length`（= 245）跑，当 `x` 到 148 时，`duration[148]` **已经超出数组末尾**，读到的是相邻内存里的数据。

**证据一：编译器直接报警**

```
warning: iteration 148 invokes undefined behavior
         [-Waggressive-loop-optimizations]
```

**证据二：实际跑出来的"垃圾值"**

我把两个数组原样搬到 PC 上跑了一遍：

```
  x=148  越界读到 duration[148] = 0
  x=152  越界读到 duration[152] = nan          ← 非数字
  x=155  越界读到 duration[155] = 5.5071e-43   ← 极小的次正规数
越界读取次数 : 97 / 245
算出延时 = 0    : 97 个音符
```

**后果**：后 97 个音符的 `delay(400 * 垃圾值)` 算出来是 **0 毫秒**，所以它们会被**瞬间跳过**。你听到的效果是：前面 148 个音符正常（约 59 秒），然后突然"唰"一下全部过完，接着静音 5 秒，再从头开始。

> ⚠️ 我这里测出的是"瞬间跳过"，但这是**运气好**的结果。越界读取是未定义行为——在真正的 UNO 上，那块内存里可能是完全不同的值。**最坏情况是读到一个巨大的数，`delay()` 卡住几分钟甚至更久，曲子直接"死"在那里。**

**这是这份代码最该修的地方。**

### 问题 2：节奏信息全部丢失

如 3.4 所述，`duration[]` 里 148 个值**全都是 1 拍**。所以即使把长度补齐，弹出来也是每个音等长，像念经而不是《遇见》。

**修这个需要懂乐谱**：得对着原曲把每个字的时值标出来（四分音符=1、八分音符=0.5、附点=0.75 等）。

### 问题 3：RAM 占用过高（54%）

```
原始版: Sketch uses 4004 bytes (12%)
        Global variables use 1112 bytes (54%)   ← 只剩 936 字节可用
```

UNO 只有 **2048 字节 RAM**，这份代码光两个全局数组就吃掉 1112 字节：

| 数组 | 元素数 | 单个大小 | 占用 |
|---|---|---|---|
| `tune[]` | 245 | 2 字节（int） | 490 字节 |
| `duration[]` | 148 | 4 字节（float） | 592 字节 |
| **合计** | | | **1082 字节** |

**问题在于**：这两个数组是**只读的常量数据**，却全放在 RAM 里。它们应该待在 Flash（32KB）里——用 `PROGMEM` 就能做到，见修正版。

### 问题 4：`tone()` 会抢占 Timer2，影响 D3 和 D11 的 PWM

这是新手最容易踩的隐形坑。

Arduino UNO 的 `tone()` 内部使用 **Timer2**。而 Timer2 同时负责 **D3 和 D11** 的 PWM 输出。

**也就是说：只要你在程序里用了 `tone()`，D3 和 D11 的 `analogWrite()` 就会异常。**

如果你之前做的 RGB 呼吸灯用的是 D9/D10/**D11**，那加上蜂鸣器之后，蓝色通道（D11）会失效或乱闪。

**规避方法**：把 RGB 的蓝色脚从 D11 换到 **D5 或 D6**（它们用 Timer0），或者换到 D9/D10（Timer1）。三个 PWM 通道分属不同定时器就不会打架：

| 定时器 | 对应引脚 | 被 tone() 占用 |
|---|---|---|
| Timer0 | D5、D6 | 否 |
| Timer1 | D9、D10 | 否 |
| Timer2 | **D3、D11** | **是** ← 用 tone() 后失效 |

### 问题 5：其他小瑕疵

- **`length` 类型**：`sizeof` 返回的是无符号的 `size_t`，赋给 `int` 变量严格来说有符号转换问题（实际不会出错，但规范写法是 `int length = (int)(sizeof(tune)/sizeof(tune[0]));`）
- **`boolean` 是旧习惯**：新版统一用 `bool`
- **文件名乱码**：`buzzer-song-___-__.ino` 里的 `___` 应该是微信传输时丢失的字符
- **注释里的 `weather`**：在别处那份代码里出现过，应为 `whether`

## 5. 修正版（已实测）

我做了个修正版，改了四处：

1. `tune[]` 加 `PROGMEM` 放进 Flash
2. 删掉越界的 `duration[]`
3. 休止符改用 `0`，显式静音
4. 循环永远不会越界

### 实测对比

| | Flash | RAM |
|---|---|---|
| 原始版 | 4004 B（12%） | **1112 B（54%）** |
| **修正版** | 2862 B（8%） | **28 B（1%）** |

**RAM 从 1112 字节降到 28 字节，省出 1084 字节。** 这才是 UNO 上健康的用法。

### 关键代码

```cpp
#include <avr/pgmspace.h>

// 音符表放进 Flash，不占 RAM
const int tune[] PROGMEM = {
  NOTE_C0, NOTE_C0, NOTE_C0, NOTE_C5, NOTE_C3,
  // ... 共 245 个
};

const int TUNE_LEN = sizeof(tune) / sizeof(tune[0]);

const unsigned long BEAT_MS  = 400;    // 一拍多长
const unsigned long GAP_MS   = 30;     // 音符间小间隔
const int tonePin = 7;

void loop() {
  for (int x = 0; x < TUNE_LEN; x++) {

    // 从 Flash 里读，必须用 pgm_read_word
    unsigned int freq = (unsigned int)pgm_read_word(&tune[x]);

    if (freq == 0) {          // 休止符：安静等一拍
      delay(BEAT_MS);
      continue;
    }

    tone(tonePin, freq);
    delay(BEAT_MS);
    noTone(tonePin);
    delay(GAP_MS);
  }
  delay(5000);
}
```

**注意 `pgm_read_word()`**：数组放进 PROGMEM 后，不能直接 `tune[x]` 访问（那会读到错的地址），必须用 `pgm_read_word(&tune[x])` 来读。这是 AVR 平台特有的要求，忘了写就会出现"音高全乱"的怪现象。

完整文件：`arduino-ir-led/buzzer_song_fixed/buzzer_song_fixed.ino`

### 想彻底修好还得补节奏

修正版把节拍统一成 1 拍（因为原数据没有可用的节奏信息）。要真正还原《遇见》，需要按原曲把每个音符的时值补出来：

```cpp
// 用 1/4 拍为单位，省内存（uint8_t 只占 1 字节）
const uint8_t duration[] PROGMEM = {
  4,4,4,2,2,     // 一拍、一拍、一拍、半拍、半拍
  4,2,2,4,2,2,   // ...
};
// 播放时：delay(BEAT_MS * pgm_read_byte(&duration[x]) / 4);
```

## 6. 硬件接线

### 无源蜂鸣器（要放歌就用这个）

```
蜂鸣器 正极 ──── D7
蜂鸣器 负极 ──── GND
```

- 无源蜂鸣器电流很小，可以直接接 IO 口
- 如果声音太小，可以在正极串一个 **100Ω 电阻到三极管**再驱动（大功率蜂鸣器才需要）

### 有源蜂鸣器

```
蜂鸣器 正极 ──── 100Ω 电阻 ──── D7
蜂鸣器 负极 ──── GND
```

- 有源蜂鸣器工作电流较大（20~30mA），**最好串一个 100Ω 电阻**保护 IO 口
- 用 `digitalWrite(pin, HIGH/LOW)` 开关就行，不需要 `tone()`

### 引脚选择注意

避开 **D3 和 D11**，因为 `tone()` 会占用它们的定时器。原代码用的 **D7** 是个好选择 ✓

## 7. 知识点速查

### `tone()` 和 `noTone()`

```cpp
tone(pin, frequency);              // 开始发声，持续到 noTone
tone(pin, frequency, duration);    // 发声指定毫秒后自动停
noTone(pin);                       // 停止
```

- 只能在**一个引脚**上同时发声（UNO 上 `tone()` 只支持 1 个引脚）
- 频率参数是 `unsigned int`，**传负数会变成很大的正数**
- 使用它就会占用 Timer2

### `sizeof` 求数组长度

```cpp
int length = sizeof(arr) / sizeof(arr[0]);
```

只对**真正的数组**有效。如果数组作为参数传给函数（退化成指针），这个写法就失效了。

### 平行数组的风险

用两个数组、靠下标一一对应，是嵌入式里常见的省内存做法，但**必须保证长度一致**。防御写法：

```cpp
int len = min((int)(sizeof(tune) / sizeof(tune[0])),
              (int)(sizeof(duration) / sizeof(duration[0])));
for (int x = 0; x < len; x++) { ... }
```

### PROGMEM：把常量放进 Flash

AVR 的 RAM 只有 2KB，Flash 有 32KB。只读的常量表应该放 Flash：

```cpp
#include <avr/pgmspace.h>

const int table[] PROGMEM = { ... };        // 定义在 Flash

int v = pgm_read_word(&table[i]);           // int（2字节）用 word
uint8_t b = pgm_read_byte(&table[i]);       // 字节用 byte
```

**代价**：读取比 RAM 慢一点（几个时钟周期），但对播放音乐完全无影响。

### 自己排查数组长度

下次拿到这类代码，加两行就能查出来：

```cpp
void setup() {
  Serial.begin(9600);
  Serial.print("tune 长度: ");
  Serial.println(sizeof(tune) / sizeof(tune[0]));
  Serial.print("duration 长度: ");
  Serial.println(sizeof(duration) / sizeof(duration[0]));
}
```

两个数字不一样，就说明有越界。
