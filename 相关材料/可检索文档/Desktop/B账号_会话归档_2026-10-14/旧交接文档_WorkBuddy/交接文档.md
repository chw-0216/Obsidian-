## 1. 目标与范围

### 1.1 目标
在**不修改、不退出、不重装**现有桌面端 Codex（账号 A）的前提下，让第二个 ChatGPT Plus 账号（账号 B）以**独立 CLI 终端**的形式同时在线，用于查本机文件、整理素材、生成文档。

### 1.2 明确不在范围内
- ❌ 桌面端双开（同一应用开两个窗口）——已放弃该路线
- ❌ 账号切换器 / 第三方多开管理器——不采用
- ❌ 复制、迁移或共享账号 A 的登录凭据、聊天历史、私人记忆
- ❌ 安装任何 PPT 生成插件或第三方工具

### 1.3 设计原则
**只隔离身份，不隔离能力。**
`auth.json`（登录身份）必须各自独立；其余配置从零建立最小可用集，不从账号 A 整份拷贝——因为账号 A 的配置含 `danger-full-access` 全盘写权限、通知程序绝对路径等**不该被继承**的内容。

## 3. 日常操作（SOP）

> 全部操作都在 `outputs\Codex-CLI-B\` 目录内双击完成，**不需要命令行经验**。

### 3.1 首次登录账号 B

1. 打开目录 `C:\Users\wardc\WorkBuddy AI\2026-10-12-08-22-20\outputs\Codex-CLI-B\`
2. 双击 **`Login-B.cmd`**
3. 终端会打印一个授权网址并自动打开浏览器
4. **授权前务必确认**：浏览器页面右上角显示的是**第二个 ChatGPT 账号**（账号 B）
   - 如果显示的是账号 A：把终端里的授权网址**复制**到另一个浏览器个人资料 / 无痕窗口 / 另一个浏览器里打开

> ⚠️ 保持终端窗口打开直到登录完成；不要关闭浏览器标签后再回来点确认。

### 3.2 日常启动账号 B

双击 **`Start-B.cmd`** —— 打开账号 B 的 CLI 交互窗口，默认工作目录为 `codex-b-work`。

**指定其他工作目录**（例如素材所在的文件夹）：
```

```

### 3.3 查看登录状态 / 确认账号身份

双击 **`Codex-B.cmd`**，菜单：
```
1. 首次浏览器授权登录      2. 设备码登录（需账号开启）
3. 启动账号 B 对话          4. 查看登录状态
5. 查看当前是哪个账号（邮箱）  0. 退出
```

- 选 `4` → 显示 `login status`
- 选 `5` → **显示当前 profile 登录的账号邮箱**，并**自动与桌面账号 A 比对**；若相同会报警告

> 启动 `Start-B.cmd` 时也会自动显示一次当前账号邮箱，防止用错身份。

## 5. 隔离原理与安全边界

### 5.1 启动器做了什么（`launcher.mjs`）

1. **锁定目录**：把 `CODEX_HOME` 与 `CODEX_SQLITE_HOME` 都指向 `C:\Users\wardc\.codex-cli-b`
2. **清除继承的敏感变量**：启动前删除所有继承来的 `CODEX_HOME` / `CODEX_SQLITE_HOME` / `OPENAI_API_KEY` / `CODEX_API_KEY` / `CODEX_ACCESS_TOKEN` / `CODEX_REMOTE` / `CODEX_REMOTE_AUTH_TOKEN` / `NODE_OPTIONS` / `NODE_TLS_REJECT_UNAUTHORIZED`，再重新设定 → **防止父进程环境污染账号 B**
3. **缺文件即报错退出**：若账号 B 目录、配置、CLI 或工作目录任一不存在，**直接报错，绝不回退到桌面账号** → 这是防串号的关键保险
4. **已登录不覆盖**：登录动作前先查 `login status`，已登录则跳过，避免误覆盖现有凭据
5. **固定登录方式**：强制 `cli_auth_credentials_store="file"` + `forced_login_method="chatgpt"`
6. **默认权限收敛**：`--sandbox workspace-write --ask-for-approval on-request`

### 5.2 隔离边界（诚实说明）

| 已隔离 ✅ | 说明 |
|---|---|
| 登录身份 | 两账号凭据各存各的目录 |
| 配置 | 账号 B 只有 5 行最小配置，不继承账号 A |
| 会话与状态 | 独立的 SQLite 与历史 |

| 未隔离 / 共享 ⚠️ | 说明 |
|---|---|
| 文件系统 | 两窗口读同一块硬盘，**素材无需复制**（这是特性，不是缺陷） |
| 网络出口 | 都走同一台机器联网 |
| 模型侧数据 | 被读取的正文内容会随请求发送给模型服务（见第 9 章） |

## 9. 已知限制与风险

1. **CLI ≠ 桌面端**。终端入口不保证拥有桌面端的 PPT 生成、预览与插件体验。**建议先用一个小样验收**；若不满足，需要另找方案（本环境不承诺解决）。
2. **不要两个账号同时修改同一份 PPT**。两边可读同一素材，但输出请用不同目录或不同文件名。
3. **「文件在本机」不等于「内容不出本机」**。联网模型读取文件正文后，被选中的内容通常会发送到模型服务。**微信隐私、医疗资料、私人记忆不应默认放进账号 B 环境**。
4. **版本固定不自动更新**，需要手动升级（见 7.1）。
5. **凭据落在本地文件**（`cli_auth_credentials_store="file"`），这是为了让凭据可见、可独立删除；请勿把 `C:\Users\wardc\.codex-cli-b\` 整个目录拷贝给他人。
6. **首次登录必须用独立浏览器会话**。若授权页显示账号 A，OAuth 会复用现有登录态，最终仍登进账号 A。

## 10. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 cmd 一闪而过 | 脚本报错退出 | 在 cmd 窗口里手动运行 `launcher.mjs check` 看报错；cmd 已带 `pause`，正常应停留 |

| 授权页显示的是账号 A | 浏览器复用了账号 A 的登录态 | 复制终端里的授权网址到**另一个浏览器个人资料 / 无痕窗口**打开 |
| 浏览器显示授权成功，但终端仍 Not logged in | 回调未完成或窗口被提前关闭 | 重新双击 `Login-B.cmd`，保持终端打开至出现成功提示 |
| 想换账号 B 的登录身份 | 已有凭据 | 删除 `C:\Users\wardc\.codex-cli-b\auth.json`，再双击 `Login-B.cmd` |
| 提示凭据已存在 / 拒绝登录 | 防误覆盖保险触发 | 按上一条先删除该目录下的 `auth.json` |
| 想确认桌面账号 A 是否被动过 | —— | 看 `C:\Users\wardc\.codex\auth.json` 修改时间是否仍为 **10-07** |
