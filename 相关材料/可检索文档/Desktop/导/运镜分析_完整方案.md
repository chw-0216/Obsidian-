# 四、运镜分类学（CameraBench · 50+ 标签）

来源：[Towards Understanding Camera Motions in Any Video](https://arxiv.org/html/2504.15376v2)（CMU/Adobe/MIT 等，与**专业电影摄影师**合作制定）

这是目前**最严谨**的运镜框架——它把很多数据集搞混的概念分开了（比如 zoom 是内部焦距变化，dolly 是外部物理位移，**不是一回事**）。

## 4.1 七个维度

### ① 运动类型（Motion type）
| 标签 | 含义 |
|------|------|
| `no` | 无运动 |
| `simple` | 清晰且一致 |
| `minor` | 微弱 |
| `complex` | 含混/冲突 |

### ② 稳定性（Steadiness）
`static`（静止）· `no shaking` · `minimal shaking` · `unsteady` · `very unsteady`

### ③ 位移（Translation）← 物理移动
| 标签 | 方向 |
|------|------|
| `dolly` | 前进 / 后退（in / out） |
| `pedestal` | 上升 / 下降（up / down） |
| `truck` | 左移 / 右移（right / left） |

### ④ 旋转（Rotation）← 原地转
| 标签 | 方向 |
|------|------|
| `pan` | 左右摇（right / left） |
| `tilt` | 上下摇（up / down） |
| `roll` | 滚转（CW / CCW） |

### ⑤ 焦距变化（Intrinsic change）
`zoom`（in / out）—— **镜头内部变化，机位没动**

### ⑥ 物体中心运动（Object-centric）
`arc`（环绕）· `tail-tracking`（跟背）· `lead-tracking`（跟前）· `side-tracking`（跟侧）· `aerial-tracking`（航拍跟）· `tilt-/pan-/arc-tracking`
以及：主体在画面中变大 / 变小

### ⑦ 其它
- **速度**：`slow` / `regular` / `fast`
- **电影化效果**：`dolly-zoom`（希区柯克变焦）· `motion-blur`
- **场景运动**：`static` / `mostly-static` / `dynamic`

## 4.2 最容易搞混的三组（论文特别指出）

| 常被搞混 | 区别 |
|----------|------|
| **zoom-out** ↔ **dolly-out** | 前者是**镜头焦距**变化，后者是**机位后退** |
| **pan** ↔ **truck** | 前者**原地转**，后者**横向位移** |
| **dolly-in** ↔ **pedestal-down** | 鸟瞰时向前推，人容易说成"下降" |

**分析时这三组必须分清**——这正是《绝对者》这类片子值得拆的地方。

# 五、开源工具栈（三层）

## 第 1 层：切分镜（必需）

| 工具 | 说明 | 安装 |
|------|------|------|
| **PySceneDetect** | 最成熟的分镜工具，`ContentDetector` / `AdaptiveDetector` / `ThresholdDetector` | `pip install scenedetect[opencv]` |
| **TransNetV2** | 深度学习的镜头边界检测，精度更高 | `pip install transnetv2` |
| FFmpeg | 底层切分，按时间码裁 | 你已有 `ffmpeg n8.1` |

官网：[scenedetect.com](https://www.scenedetect.com/docs/0.6.6/api/detectors.html)

## 第 2 层：识别运镜类型

| 工具 | 说明 |
|------|------|
| **⭐ `gen-ai-team/kandinsky-video-tools`** | 专门评估**物体与镜头运动**的模型集（Sber AI） |
| **⭐ `ai-forever/kandinsky-videomae-large-camera-motion`** | VideoMAE 微调的**运镜分类**模型，`transformers` 直接调 |
| **⭐ `lewholel-maker/Video-Analysis-AI-Agent-System`** | **中文项目**：基于 LLM 分析**镜头维度、运镜方式、镜头衔接**并出评分报告 |
| MovieNet | 数据集（含镜头类型+运镜标注），可做参考/微调 |

## 第 3 层：几何验证（防误判）

| 工具 | 用途 |
|------|------|
| **OpenCV** `calcOpticalFlowFarneback` / `DISOpticalFlow` | 稠密光流 → 判断全局运动方向 |
| **OpenCV** `findHomography` + RANSAC | 估计帧间单应矩阵 → 反推 pan/tilt/zoom |
| **RAFT** / **Kornia** | 更准的光流（深度学习） |
| **COLMAP** / **MegaSAM** | SfM 求相机轨迹（论文实测：MegaSAM 比 COLMAP 好 1-2 倍） |

**为什么要第三层**：论文实测发现，SfM 类方法处理**动态场景**容易把"物体运动"误判成"镜头运动"；而 VLM 类方法容易搞错**几何方向**（把 tilt-down 说成 tilt-up）。**两层交叉验证才可靠。**

## 步骤 4：几何验证（可选但推荐）

```python
import cv2, numpy as np
cap = cv2.VideoCapture("shot_001.mp4")
ret, prev = cap.read()
prev_gray = cv2.cvtColor(prev, cv2.COLOR_BGR2GRAY)

while True:
    ret, cur = cap.read()
    if not ret: break
    cur_gray = cv2.cvtColor(cur, cv2.COLOR_BGR2GRAY)

    # 稠密光流 → 看全局运动方向
    flow = cv2.calcOpticalFlowFarneback(prev_gray, cur_gray, None,
                                        0.5, 3, 15, 3, 5, 1.2, 0)
    mag, ang = cv2.cartToPolar(flow[...,0], flow[...,1])

    # 依据主方向 + 幅值判断：
    #   方向一致 + 幅值稳定  → 平移（dolly/pedestal/truck）
    #   朝四角发散/汇聚      → zoom in/out
    #   整体同向旋转         → pan/tilt/roll
    prev_gray = cur_gray

cap.release()
```

**判据速查**：

| 光流特征 | 运镜 |
|----------|------|
| 全画面同向、幅值均匀 | **平移**（dolly / pedestal / truck） |
| 向外辐射发散 | **zoom in** |
| 向内汇聚 | **zoom out** |
| 全画面同向旋转、中心幅值小 | **pan / tilt** |
| 画面整体绕中心转动 | **roll** |
| 主体位置不变但背景变化 | **tracking**（跟拍） |

# 七、零安装方案：直接问多模态模型

如果不想配环境，**把每个镜头截图（首/中/尾 3 帧）喂给 Gemini，问固定的 7 组问题**：

```
这是一段视频的 3 帧（开头/中间/结尾）。请只回答以下问题，不要推测：
1. 机位是否移动？向前/后、上/下、左/右？（dolly / pedestal / truck）
2. 镜头是否旋转？左右摇、上下摇、还是滚转？（pan / tilt / roll）
3. 焦距是否变化？推近还是拉远？（zoom in / out）
4. 机位是否在原地不动，只有画面变化？
5. 是否在跟随某个运动主体？跟的是背面/正面/侧面？（tail/lead/side-tracking）
6. 运动速度：慢 / 正常 / 快？
7. 是否有希区柯克变焦（dolly-zoom）或运动模糊？

不确定的请写「不确定」，不要猜。
```

**关键：让它对每个镜头独立回答**，别让它一口气描述整片——论文实测 VLM 整片描述误判率很高。
