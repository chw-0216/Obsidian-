一、问题是什么

先分清两层。用户看到的是「重复」，实际存在两个独立问题：

问题 A · 重复 2,450 条

  • 源库 0 重复（947,355 行，server_id 唯一）
  • 100% 由索引层引入
  • 集中在群聊（1,728 条）
  • 影响：统计类指标虚高 0.77%

问题 B · 覆盖只有 34.3%

  • 源库 947,355 vs 索引 324,588
  • 缺口 96% 集中在 2 个刷屏群（家教派单）
  • 剔除后覆盖 92.5%
  • 群聊长尾仍有 ~25,000 条没进来

根因：去重键类型不匹配

index-incremental.py 里，预载已有消息时用 3 元组，检查新消息时用 4 元组：

# 预载（旧，第 122-124 行）
for sk, ts, ct in idx.execute(
        "SELECT session_key, ts, substr(content,1,80) FROM messages WHERE ts >= ?", ...):
    seen.add((sk, ts, ct))                    # ← 3 元组

# 检查（第 194 行）
key = (sid, ts, text[:80], sender)            # ← 4 元组
if key in seen:                               # ← 永远为 False
    continue

两个集合元素的形状不同，所以 key in seen 恒假 —— 跨轮去重从未生效过。其余脆弱点：预载只回溯 3 天、内容截断到 80 字、重读窗口仅 60 秒、从不回填历史。

为什么 221 组「同秒同文」不是重复

新库按内容键仍能测出 221 组同秒同文，但它们的 server_id 各不相同 —— 是源库里真实存在的多条消息，典型如多人同秒进群（群系统消息 xxx@chatroom: 占位）、进群语音、撤回提示。这些不能删，删了才是数据损坏。
