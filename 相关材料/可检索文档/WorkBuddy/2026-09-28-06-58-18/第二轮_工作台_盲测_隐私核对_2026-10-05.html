关键设计：把筛选条件预计算成属性

Bases 的表达式语法在不同 Obsidian 版本上有差异。所以 条件全部在生成时算好，.base 里只写最简单的 x == true —— 版本无关，不会因为语法变动失效。

属性含义
need_confirm需要你本人确认（结论：待核实或有效但未确认；事件：A 级且未复核）
weak_evidence证据薄弱（A 级事件里证据质量为「低」或「无」）
has_counter结论带反例 / 红线
action事件性质是「计划」或「进行中」，且日期 ≥ 2026-07-01
evidence_quality高 / 中 / 低 / 无（按回链结果算）

用法：Obsidian 里直接点开 .base 文件 → 就是一张可排序、可筛选、可导出 CSV 的表。也能嵌进别的笔记：![[① 待本人确认.base#结论 · 待拍板]]。

三、隐私核对：9 项

3.1 ★ 已修复：Ollama 曾监听所有网卡

发现：用户环境变量 OLLAMA_HOST = 0.0.0.0。0.0.0.0 不是默认值 —— 二进制里写得很清楚：IP Address for the ollama server (default 127.0.0.1:11434)。

影响：Ollama API 没有鉴权。绑定 0.0.0.0 意味着同一 WiFi 下任何设备都能：列模型、跑推理（吃你的 GPU）、拉模型（占满磁盘）。日志里 2026-08-22 确实出现过 Listening on [::]:11434。

但：翻遍 262 条请求记录，全部来自 127.0.0.1，一次外部访问都没有 —— 说明这个设置从未被真正用上，是遗留配置。

处置：已改为 127.0.0.1:11434（重启 Ollama 后生效）。
想改回去：setx OLLAMA_HOST 0.0.0.0（若你确实要从手机/别的电脑访问，请同时加防火墙规则）。

3.2 ★ 已修复：Ollama 云功能

写入 C:\Users\wardc\.ollama\server.json → {"disable_ollama_cloud": true}。实测启动日志确认生效：

msg="Ollama cloud disabled: true"
msg="Listening on 127.0.0.1:11434 (version 0.32.1)"

另外说明：日志里仍有对 github.com（19 次）和 ollama.com（2 次）的请求 —— 那是版本更新检查，不含聊天内容。关掉云功能不影响它，也不需要关。
