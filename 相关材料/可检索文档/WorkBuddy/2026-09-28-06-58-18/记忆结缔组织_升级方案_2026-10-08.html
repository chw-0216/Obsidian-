0结论先行

你的底座不用换。缺的不是工具，是「结缔组织」——让同一件事不被重复算成多份证据、让旧结论会失效、让你的人工纠正机器可读。

首版只装 1 个新东西（QMD 中文检索层），其余全部在现有 analysis.sqlite 上加表实现。

五条核心判断

  1. 工具不缺，缺连接。你已经有了对的那套骨架——conclusions 表里本来就有 counter_examples / verdict / self_confirmed / valid_from / valid_to 五个字段。问题不在表设计，在于没人往里写（64 条结论、4 条修订，而 persons/aliases 是 0 行）。
  2. 只装一个。Graphiti / Cognee / LightRAG / HippoRAG / Second Me 全部缓装——它们解决的是"文档问答"或"对话缓存"，不是"39 万条人生记录 + 人工裁定"。
  3. 图谱先用 SQLite 表达。双时态（事实带有效期）你表里已有两列，补一个"失效触发"逻辑就够，不必上 Neo4j。
  4. 「更激进」= 溯因引擎，零安装。把「一个结论」改成「3 个竞争假设 + 各自反证 + 判别观测」。这是纯流程改造。
  5. 统一入口 = 阅读包 + MCP。所有 harness 从同一处取状态、交结论；人工纠正单独存，不被下一轮生成覆盖。
一句话纠正你粘贴那版方案
它把重点放在"装什么工具"上。但按实测，你最大的技术缺口是 persons / aliases 两张空表——你的"人"现在只活在 Obsidian 笔记和 CSV 里，数据库里根本没有。这就是"信息配合不起来"的根因。不修这个，装什么检索层都白搭。

4.2 要补的 4 张表

-- ① 来源登记：一切去重的根
create table if not exists sources(
  source_id    text primary key,
  kind         text,   -- wechat|obsidian|file|web|photo|audio
  path         text,   -- 文件/会话定位
  content_hash text,   -- 正文哈希 → 去重
  first_seen   text,
  last_ok      text,   -- ★ 最后成功读取时间（必须对外显示）
  privacy      text    -- local_only | masked_ok
);

-- ② 假设：与结论分离，允许多条并存
create table if not exists hypotheses(
  hyp_id             text primary key,
  statement          text,   -- 假设本身
  about_event        text,   -- 针对哪件事
  supports           text,   -- 支持证据
  counters           text,   -- ★ 反证（必填）
  discriminating_obs text,   -- ★ 判别观测：看到什么能区分真假
  status             text,   -- open|supported|refuted|merged
  created_at text, updated_at text
);

-- ③ 决策卡
create table if not exists decisions(
  dec_id     text primary key,
  question   text,   -- 当时问的是什么
  goal       text,   -- 服务哪个目标
  options    text,   -- 备选
  chosen     text,   -- 实际选了哪个
  why        text,
  expected   text,   -- 预期结果
  outcome    text,   -- ★ 实际结果（回填）
  reviewed_at text
);

-- ④ 程序记忆：怎么查、怎么验
create table if not exists procedures(
  proc_id  text primary key,
  trigger  text,   -- 什么情况下触发
  steps    text,
  source   text,   -- 人工|复盘|论文
  applied  integer, success integer
);
最高优先级：回填 persons / aliases
这是治本的一步，且零安装。你的 Obsidian 有 458 份人物档案、引擎有 距离地图.csv（98 人）——把这些灌进 persons/aliases，数据库里才第一次"有人"。之后任何检索都能按人聚合，而不是按关键词瞎撞。

5让分析「更激进」：溯因引擎

「激进」不是把假设当事实说死，而是多提假设、强制找反证、强制跨域。这是零安装的流程改造。

先立红线：激进 ≠ 违规
你引擎里有 12 条红线（不得推断未裁定项、不得污名化同门、不得把「父母冷战」当数据事实…）。「更激进」只作用在"提假设"这一步，不作用在"下裁定"这一步。AI 产出一律先登记为 hypothesis，你确认后才升 ruling。

（<2 个域 = 分析未完成）

稳妥方案：……    进取方案：……    探索方案：……
（比：收益 · 投入 · 机会成本 · 可逆性 · 对其他目标的影响）

最小行动：……    观察什么：……    什么情况下改判：……
置信度：高 / 中 / 低（依据：……）
（未校准前，禁止写"87% 概率"这类精确数字）

5.3 「激进」的三个具体化

① 跨域强制
每次分析必须跨 ≥2 个域（钱/关系/学业/作品/身体/时间）。只谈一个域的结论，一律退回重做。这是防"只看到关键词命中"。
② 人格模拟
写一段「如果我是他，我会怎么想」的第一人称推演——但必须标注为假设，不得当事实。这是"像一个人来分析"的落地形式。
③ 反直觉假设
每次至少 1 条与直觉相反的假设。例如："你持续开新项目，不是因为你贪多，而是因为整理旧成果会让你面对'它们还不成形'。"
④ 反证优先
先找反证，再写结论。每个结论必须挂 ≥1 条 counter_examples（你表里已有这个字段，只是没填）。

6跨 harness 统一入口

你现在装了 4 个 MCP，其中 memory（@modelcontextprotocol/server-memory）目前是个几乎没用的 JSON 知识图谱——它正好可以升级成"公共状态"的出口。

6.1 统一入口要提供 6 件事

  1. 搜原文、定位证据

8红线与风险

#风险对策
1隐私外发：本地 MCP 把原文返回给云端模型时，内容仍然外发sources.privacy 分 local_only / masked_ok；深度分析走本地 Ollama
2算力：16GB 内存不跑本地大模型全量抽取；嵌入模型 0.6B 级可跑
3中文效果不确定先用真实问题小样本测，达标再常驻；检索分数 = 相关度，不等于事实可信度
4精确概率误导未校准前不写「87% 概率」这类数字
5「装了就会理解」的幻觉没有任何工具能保证"安装即理解一个人"。决定效果的是建模 / 连接 / 纠错 / 反馈
6AI 结论污染人工锚点AI 产出先登记 hypothesis，你确认后才升 ruling
7增量更新拖垮机器现有全量生成脚本不能每次存笔记就跑；拆出轻量增量，避免扫描自身输出

更新节奏（三档）

  • 文件变化后：合并短时间连续修改 → 更新文件清单 / 版本 / 检索索引
  • 电脑空闲时：抽新增事件 → 发现别名与重复来源 → 检查矛盾 → 标记受影响结论
  • 定期复盘时：重估目标 / 未完成承诺 / 资源冲突 / 决策结果，只推有实质影响的变化

每个数据源都要显示「最后成功读取时间」。上游聊天导出没更新，系统必须承认资料停在旧日期。
