# 记忆与纠正回归

[[09_研究与实验/00_研究总览|研究总览]] · [[04_工作台/行动/ACT-R01_验证记忆与纠正|对应行动]] · [[09_研究与实验/记录模板/R01_回归与复核记录|逐题与复核记录]]

这项实验分两层：先确认来源版本变化能够进入持久复核队列，再检验系统回答是否正确使用时点、来源与撤回状态。工程联调通过只能证明前一层；24条虚构问答全部保留为待执行，不能用工具测试数代替。

## 要回答的问题

在相同资料和提问下，当前读取方式是否会引用已失效依据、把后录入的信息泄漏到历史答案，或把同一来源的多份摘要重复计票？候选改进是明确的时间过滤、来源族与复核依赖；哪个环节实际有效，由逐题记录判断。

## 输入和开始条件

| 测试资料 | 每题独立的虚构资料副本；来源、结论、建议ID互不冒充生产ID | 不把测试纠正、撤回写入真实 `analysis.sqlite` |
| 比较基线 | 固定当前读取入口、模型版本、提示词、资料快照及文本预算 | 当前入口无法回答时记 `未实现`，不能按“未知且正确”计分 |

真实资料的问答评测是后续阶段。桥接工具可读取真实数据库对象的版本与依赖变化，但这不等于已经实现对真实资料的问答评测；起步不需要导入聊天原文。

## 前30分钟怎样开始

以下是一次工作段的操作顺序，不是已安排的用户日程。

1. **0至5分钟**：在库外建立本次运行目录，复制[[09_研究与实验/记录模板/R01_回归与复核记录|记录模板]]，填 `run_id`、工具版本和题集哈希；原始回答栏留空。
2. **5至10分钟**：运行工具目录的联调入口，保存控制台摘要及报告路径。核对“读取的库”“状态文件”“报告目录”三处；状态和报告必须在库外。首次扫描无变化提示是建立基线，不是全部结论正确。
3. **10至15分钟**：查看持久队列。若队列为空，不为演示去改真实依据；在工具的合成测试夹中检查“源变化→实验页→行动页”的样例。区分本次新增、仍待复核、已人工处理。
4. **15至20分钟**：选 T02、P02、U01、D02 四题作为冒烟样例，分别覆盖迟到补录、引文不符、未知和多层依赖。把各题独立输入与期望输出放入本次目录。
5. **20至25分钟**：对接已经存在的读取入口。若接口只接受真实数据库或不支持所需时点，记录“未实现的参数/接口”，停在接入缺口；不要改用自由对话回答来假装接口通过。
6. **25至30分钟**：若接口可用，逐题保存原始输出、来源ID、拒答状态和耗时，人工判一条失败原因。若接口不可用，交付四题输入与缺口清单，24题仍为未执行。

## 工程联调具体看什么

`evidence_watch.py` 提供文件哈希变化与显式依赖路径；`research_bridge.py` 把研究层与行动层的明确依赖接入库外持久队列。它读取09研究页及 `04_工作台/行动` 的 `depends_on`，所以研究依据变化可以继续传到行动复核；它不把当前行动直接改成已完成或已取消。

本页 `review_scopes` 声明监测 `self_claims` 与 `recommendations`，用途是把相关数据库变化分派到本实验复核，不表示本文理论依赖于每一条私人事实。若需绑定某条具体对象，应使用工具支持的明确 `db_refs` 并说明理由；不在模板中猜造真实ID。

在工具目录用以下接口；`V` 为真实Vault，`D` 为现有 `analysis.sqlite`，`S` 为库外“桥接状态”目录，`O` 为本次库外报告目录。D只读，S中的派生状态才可写。

```text
research_bridge.py scan --vault V --database D --state-dir S --out O
research_bridge.py queue --state-dir S --out O
research_bridge.py ack --state-dir S --item 实际队列ID --resolution keep --note 实际人工理由 --out O
```

`scan` 首次建立基线；`queue` 只列出已有队列；`ack` 是明确人工复核后的操作。`resolution` 使用 `keep`、`revise`、`supersede`、`insufficient`，分别表示保留、修正、替代和信息不足。上面的“实际队列ID/实际人工理由”是说明占位，不能原样运行。`insufficient` 记录理由但保持待复核，不伪装成问题已经解决。具体入口还见[[09_研究与实验/07_工具与使用说明|工具使用说明]]。

- **首次运行**：建立基线并单列缺失依赖；不制造“所有页面刚刚失效”的批量事项。
- **来源变化**：展示旧新版本、起点与影响路径；只提示需要复核，不判断旧结论已错。
- **再次扫描**：同一变化不得无限重复入队；未处理事项应仍能在持久队列找到。
- **人工复核**：先阅读变化和影响，再记录决定与理由。`ack` 不修改来源、旧建议或原项目状态；信息不足仍留在待复核队列。
- **删除与循环**：缺失保留为缺口，循环有限结束；不得静默丢掉受影响分支。

## 24题的对照与判定

先冻结 A 为当前读取方式；B 只增加明确的来源/时间过滤。只有 A、B 的记录完整且存在已定位缺陷时，才加入图或语义扩展 C。三者使用相同题集、资料、模型和文本预算；分别报告未实现、失败、通过，不能只展示可回答的子集。

| 记录项 | 判定办法 |
|---|---|
| 证据召回 | 必需的标准证据ID是否返回；分母是该题必需证据数 |
| 最终回答 | 是否处于允许回答范围；引文能否支持所述事实 |
| 拒答 | 无记录、冲突或失效前提下是否按题目要求保留未知 |
| 时间正确性 | `world_as_of` 与 `known_as_of` 是否分别生效，迟到材料是否泄漏 |
| 独立来源数 | 按来源根计数，而不是按笔记/摘要条数计数 |
| 传播范围 | 受影响对象是否恰当，未依赖分支是否保持不变 |
| 成本 | 保存索引/冷启动时间、每题查询时间与输出文本量，不能混成一个延迟值 |

先执行四题冒烟，再执行全部24题。撤回和未知题出现确定失效建议、测试写入真库、无法保存原始输出，任一发生即停止扩展。失败题需在修复后用同一输入重跑；新的成功不能删除旧失败记录。

## 失败后怎么回写

接口未实现写入对应行动的阻碍与下一步；工具错误引用复现文件；研究方法不适用则回写所依赖研究页的适用边界。实验实测后将本页 `outcome_status` 改为进行中或已观察，并同步 `actual_result` 与“实际结果”；观察到失败同样可以记已观察。行动是否完成按其验收另判，不因有结果就自动完成。

旧系统入口仍是[[08_多维导航/04_证据核验|来源核验]]、[[06_自我模型/建议与依赖链|既有建议依赖]]和[[07_决策中枢/05_反馈与修订|反馈]]；对它们的修改沿原生成器及人工回写入口进行。
