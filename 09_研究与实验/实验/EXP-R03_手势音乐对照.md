# 手势音乐对照

[[09_研究与实验/00_研究总览|研究总览]] · [[04_工作台/行动/ACT-R03_比较手势稳定与演奏控制|对应行动]] · [[09_研究与实验/记录模板/R03_手势对照记录|运行与对照记录]]

问题是减少误触发能否同时保留演奏控制。先确认现有乐器怎样工作，再比较单一变化；曲线更平滑并不自动代表更容易演奏。

## 本地基线已经有什么

[[01_个人信息/项目/双手成曲-GestureSynth|项目原页]]给出的代码目录是 `C:\Users\wardc\Documents\New project gpt\AI-archive\apps\gesture-synth\`。本轮读取该目录 `README-CN.md` 与 `main.js`，没有运行摄像头或修改代码。

读取到的基线含和弦稳定处理、连续量平滑、声音试奏和合成器录音。README记载约85毫秒和弦稳定窗及约160毫秒丢手淡出；它们是配置说明，不是实测动作到出声的延迟。**A必须定义为当前完整实现，不能称为无处理的原始输入。**

录音保存的是合成器声音，不是摄像头视频、人声或逐帧手部关键点；页面刷新会丢失未下载录音。会话内事件记录不等于已有可导出的关键点回放集。本轮未确认轨迹导出/重放接口，滤波A/B尚不能只靠现有录音按钮完成。

## 输入和开始条件

- 能启动本地应用、播放试奏声音；摄像头演奏需要使用者主动许可。没有摄像头时可以先测声音和手动映射，不填手势识别结果。
- 固定浏览器、窗口大小、光照、摄像头位置、左右手设置、调性、音色和映射；把真实设置写进模板。
- 选三个任务：保持同一和弦、缓慢跨越相邻手势、快速按给定顺序切换。预先写期望和弦序列，不在看到结果后修改。
- 原项目许可证与署名保留；此实验设计不授权改变原软件许可或公开发布私有录像。

## 前30分钟怎样开始

1. **0至5分钟**：读本地 `README-CN.md` 并复制[[09_研究与实验/记录模板/R03_手势对照记录|对照模板]]；记录 `main.js` 的版本标识或哈希、浏览器和本次设备。启动/停止只按原项目 `START.cmd`、`STOP.cmd`，不新建另一套后台服务。
2. **5至10分钟**：使用“先试试声音”，检查音量可控、握拳/停止逻辑的说明与页面操作。未正常发声先记启动故障，不进入滤波研究。
3. **10至15分钟**：使用者若愿意开启摄像头，选单手入门与一个固定调性；保持一个已知和弦，记录界面显示是否跳动、是否误停或持续发声。不要此时改阈值。
4. **15至20分钟**：各做一段保持、慢变、快变的短基线演奏，建议每段15秒；记录期望序列和肉眼可判的异常。三段只是起步记录，尚不足以评判滤波方案优劣。
5. **20至25分钟**：下载各段合成器录音，按 `A_任务_重复序号` 命名；人工记录误触发、漏触发和“跟不上/过敏/不确定”的具体时刻。音频不能提供的手势起点记未知。
6. **25至30分钟**：结束演奏释放摄像头，确认录音文件能打开，列出当前最常见的一种失败及下一工程需求。若追踪频繁丢失，先修场景与识别，不先叠加滤波。

这30分钟只建立现状基线。未开发关键点记录和重放之前，不宣称做成“同轨迹A/B实验”。

## 第二阶段怎样做可信对照

在原项目的隔离副本中增加轨迹记录/重放入口后，才开始滤波对照。记录器需保存单调时间戳、帧序号、左右手身份、有效性标记、每个关键点坐标、输入设置及预期事件；丢失帧不能插成正常手势。不要为记录而开启麦克风。

| 条件 | 唯一变动 | 保持固定 |
|---|---|---|
| A 当前基线 | 无 | 当前稳定窗、连续平滑、映射和声音引擎 |
| B 关键点滤波候选 | 在同一关键点流加入1€ Filter，记录全部参数 | A中其他配置原样保留 |
| C 后续独立试验 | 若B无效，再单独调整触发滞回或稳定窗 | 不与B同时更改来混淆原因 |

静止、慢变、快变三类各准备相同长度的轨迹，起步可各3段；同一轨迹重放到A/B。数据缺失、设备和输入时间轴也要一致。真人演奏另作A/B体验记录，不能把两次不同手动作当成算法对照。

## 怎样判误触发和延迟

先给每个预期和弦指定可接受的转换窗口。窗口由任务节奏决定，并在观察前写入记录；没有定义窗口，不计算漂亮的准确率。

- **误触发**：期望保持区间内出现非目标和弦；同时记录次数和持续时间，避免把一长段错音拆成几十次错误。
- **漏触发**：明确的目标转换在预设窗口内未出现；没有可靠手势标注的区间记无法判定。
- **输入处理时间**：从一帧进入算法到输出映射事件；只说明软件局部耗时。
- **端到端延迟**：需要可同步的真实动作起点与实际出声证据。没有测量设备或可靠同步方法时留空，不拿85毫秒稳定窗、动画帧间隔或函数耗时替代。
- **控制感**：记录具体时刻的迟钝、意外切换、难以维持和疲劳，以及使用者实际偏好；不替本人填写评分。

B只有在同轨迹错误减少、未增加不可接受的漏触发，并且实际演奏者能够接受响应时，才进入候选采用。阈值尚待真实任务确认；若快速变化变差则退回A或降低滤波强度。保持原基线和失败日志，不为曲线漂亮删除反例。
