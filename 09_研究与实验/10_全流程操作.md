# 全流程操作

[[09_研究与实验/00_研究总览|研究总览]] · [[09_研究与实验/运行视图/当前联调结果|当前联调结果]]

## 第一次使用

打开本任务输出中的“研究工作台工具”文件夹，右键 **一键联调.ps1**，选择“使用 PowerShell 运行”。它按顺序做结构体检、数据库与笔记依赖扫描、合成评测，并更新本库唯一的生成页“当前联调结果”。新的报告使用独立时间目录。

第一次扫描建立基线。之后文件或数据库对象变化，会进入持久复核队列；未处理事项在下次仍然可见。扫描不改人物结论、建议、实际选择或行动完成状态。

## 新收一份研究资料

先填 [[09_研究与实验/模板/模板_研究来源|来源模板]]：它回答哪个问题、哪些结论有依据、什么情境不适用。只把实际采用的来源接到对应实验；普通“相关”链接不放进depends_on。

加入本地依据时使用完整路径，属性示例：

```yaml
depends_on:
  - "[[09_研究与实验/理论/02_证据与决策校准]]"
```

改完后再运行一键联调。被引用文件变了，应检查下游受影响项；格式调整也会触发文件哈希变化，可以核对后记录“保留，只有排版变化”。

## 开始一轮实验

先读对应实验的“前30分钟”步骤，准备记录卡，明确基线和验收条件。把对应行动页状态改成“进行中”；实验执行状态也同步，但不要把方案已写好记成结果已观察。尚未决定是否做的三条作品路线保持待澄清。

真实数据只写记录卡或原项目文件，实验页链接它。本人选择理由仍放原有自我模型输入区，不在研究层重复构建另一个人物模型。

## 看到一项待复核

1. 在运行视图找到编号，打开该轮库外报告看变化字段、对象ID和影响路径。
2. 文件变动回到文件；数据库对象变动按稳定ID回到原有自我模型或建议记录。先核对依据，不先改变结论。
3. 需要修改原判断时，通过既有人工区和回写工具处理。当前工具只负责提示，不代替原系统的裁定。
4. 右键运行 **提交复核结论.ps1**，输入复核编号、处理结论和说明。信息不足的事项继续保留；其余处理留有记录。
5. 重新运行一键联调，核对持续队列。关闭复核事项不等于实验完成，也不等于原数据库已改对。

虚构例：理论页只改标点，核对后可保留；实验删掉了某个重要对照条件，则先修正方案，再提交复核说明。示例不是实际复核结论，不能自动填入队列。

## 记录结果与结束

把实际记录、失败、缺失与限制写齐后再判断是否完成。R01把工程局部通过、24题完整判定、真实使用效果分开。作品实验把指标变化与主观体验分开，美育把项目贡献与唯一因果分开。

任务完成至少有对应结果路径与简要说明；`completed_at`只填真实完成日期。模板里所有示范都标为虚构，复制时先清空示范内容。

## 出现异常

| 异常 | 怎样处理 |
|---|---|
| 运行视图被手工修改 | 程序保留内容并拒绝覆盖，先把人工内容另存再核查，不强制覆盖 |
| 出现未识别关系或字段 | 查接入边界报告；未识别项不自动传播，不代表关系不存在 |
| 数据库忙、路径失效 | 本轮不能视为完成；保留旧队列，修好路径后重跑 |
| 24题显示未实现 | 这是能力缺口，不按失败模板伪造答案；进入下一工程任务 |
| 没有新变化，但还有旧队列 | 正常；逐条核对后提交结论，扫描不会自行关闭 |
