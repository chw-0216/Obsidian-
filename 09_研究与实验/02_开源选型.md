# 开源选型

当前保留 SQLite 主库，优先借鉴 Graphiti 的时间与来源机制、MemGPT 的分层上下文，再用小规模检索实验判断是否需要图结构。五个项目用于机制参考或独立试点，不同时接入主系统。验收依据见 [[09_研究与实验/理论/01_时态记忆与检索评测]]，返回 [[09_研究与实验/00_研究总览]]。

## 五个实现的采用条件

成熟度与适配判断用于本库选型；仓库功能说明和论文成绩不等于本地复现结果。以下许可证指仓库代码，模型与依赖另有各自许可。

| 实现与代码许可 | 最适合借鉴什么 | 本地运行与维护代价 | 采用条件 |
|---|---|---|---|
| [Graphiti，Apache-2.0](https://github.com/getzep/graphiti) | 双时态、原始事件与派生事实分层、来源回溯。 | 工程接口较完整；需图数据库、抽取、嵌入及重排。可接本地模型，但官方提醒小模型结构化输出可能失败。 | 先在 SQLite 旁路验证时间与纠正；只有图检索稳定优于简单基线，才引入图数据库。 |
| [Letta Code，Apache-2.0](https://github.com/letta-ai/letta-code) | 有容量预算的工作记忆与长期归档。 | 完整智能体平台，迁移成本高；本地保存状态与本地推理需分别配置。 | 只提取上下文组织机制；需完整智能体运行环境时才单独试点。 |
| [Mem0，Apache-2.0](https://github.com/mem0ai/mem0) | 提取候选记忆、关键词与语义等多路检索。 | SDK 集成较方便，算法仍在变化；抽取模型及向量存储仍需运行。 | 候选只追加、变更可审查；保留原文与来源身份，不能让自动记忆管理直接覆盖主库。 |
| [LightRAG，MIT](https://github.com/HKUDS/LightRAG) | 公开研究资料中的细节与主题双层检索。 | 服务、界面、存储和离线配置较完整；需维护抽取与索引，更换嵌入模型可能重建索引。 | 先对公开论文做阅读助手；每个结论返回原段落，评测通过后再扩大范围。 |
| [HippoRAG 2，MIT](https://github.com/OSU-NLP-Group/HippoRAG) | 查询相关三元组过滤、段落节点与图扩展。 | 有复现代码和标准检索基线，偏研究框架；本地示例涉及 70B 模型与较大嵌入模型。 | 确有跨笔记多跳问题，且同模型同文本预算下获益，才保留图扩展。 |

## 论文证据和当前实现的差别

**Graphiti 与 Zep。** [Zep 论文，2025](https://arxiv.org/html/2501.13956v1)的 LongMemEval-S 实验使用托管 Zep API。GPT-4o 基线 60.2% 与 Zep 71.2% 相差 11 个百分点，不能把托管服务的延迟或准确率当成本地开源部署保证。论文也注明来源双向索引未被直接实验检验。

**Letta 与 MemGPT。** [MemGPT 论文，2023，2024 修订](https://arxiv.org/abs/2310.08560)支持分层上下文用于长文档和多会话；它不证明自动形成的自我解释准确。[Letta 官方入口](https://github.com/letta-ai/letta)现将当前源码指向 Letta Code，旧 V1 服务在 `archive` 分支，部署前应固定版本。模型可写的工作记忆仍需经过本库的来源与修订规则。

**Mem0。** [2025 论文](https://arxiv.org/html/2504.19413v1)采用 ADD/UPDATE/DELETE/NOOP；图版本并非全面占优，多跳 judge 分数从基础版 51.15 降到 47.19。当前官方 README 的 2026 方案改为 ADD-only，并明确所列高分包含托管平台的专有优化，不能当作 OSS SDK 成绩。本地部署需同时配置 [LLM](https://github.com/mem0ai/mem0/blob/main/docs/components/llms/models/ollama.mdx) 与 [嵌入模型](https://github.com/mem0ai/mem0/blob/main/docs/components/embedders/models/ollama.mdx)，只替换其中一个仍可能向外发送文本。

**LightRAG。** [论文，2024，2025 修订](https://arxiv.org/html/2410.05779v3)主要评价四类教材语料上的自动生成问题与模型比较回答，适合支持文献综合探索；不能据此推断它能正确处理个人事实纠错、时态真值或因果判断。

**HippoRAG 2。** [论文，2025 / ICML](https://arxiv.org/html/2502.14802v1)评价公开事实问答、多跳问答与长叙事理解。保留概念及原段落有借鉴价值；脑启发设计不等于实现人的记忆，更不等于获得对本人行为的可靠解释。

## 选型顺序

1. 先验证已有时间、来源、版本和依赖字段的实际行为。
2. 在派生索引上比较简单检索与混合检索，记录正确性、拒答、成本和延迟。
3. 只在明确失败案例上试验图扩展或分层工作记忆。
4. 固定通过验收的组件版本；保留撤销组件、重建索引的能力。

不因“前沿”迁移整个知识库，不用单一排行榜决定选型，也不把生成摘要反复作为新的独立证据。是否采纳，以本库的纠正闭环和实际使用收益为准。
