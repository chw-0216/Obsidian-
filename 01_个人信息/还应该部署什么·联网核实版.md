## ① P0 · WeKnora 知识库 → MCP（最值）

### 为什么这是必做

WeKnora **v0.8.2 新增了内置 MCP Server** —— 能把知识库直接发布成 MCP 端点，给 Claude / Cursor / VS Code / **WorkBuddy** 调用。官方原话：

> 「每个空间都可以把知识库发布为 MCP 服务，供 Claude Desktop、Cursor、Claude Code、VS Code 等支持 MCP 的客户端直接检索和提问，**无需再单独部署 MCP 进程**。」

**这意味着**：你那 486 篇（人物档案 450 / 情感线 6 / 事件库 2 / 方法论 8 / 资产 8 / 个人信息 11）一旦灌进去，我在对话里就能直接查。

### 怎么配

**第 1 步**（Docker 起来后）：设置 → 发布集成 → MCP Server → 新建端点

| 配置项 | 填什么 |
|---|---|
| 名称 | 随便，如 `wechat-kb` |
| 知识库范围 | 选微信知识库（**留空 = 全部**） |
| 工具清单 | 勾「检索与阅读」+「问答」（**写入组保持关闭**） |
| 每分钟上限 | 默认 60 次 |

创建后**一次性展示**端点地址 `/mcp/<endpoint_id>` 和令牌 `mcp_xxxxxxxx`（**只显示一次，记得存**）。

**第 2 步**：WorkBuddy 是 stdio 客户端，WeKnora 是 Streamable HTTP，需要 `mcp-remote` 桥接（已验证存在，v0.14.3）：

```json
{
  "mcpServers": {
    "weknora-kb": {
      "command": "npx",
      "args": [
        "-y", "mcp-remote",
        "http://127.0.0.1:8080/mcp/<endpoint_id>",
        "--header", "Authorization: Bearer mcp_xxxxxxxx"
      ]
    }
  }
}
```

> 端口说明：WeKnora 前端 `:80`、后端 `:8080`。若走前端反代，地址用 `:80`；直连后端用 `:8080`。

### 暴露出来的工具（可勾选）

| 组 | 工具 | 用途 |
|---|---|---|
| 检索与阅读 | `list_knowledge_bases` · `search_knowledge` · `grep_chunks` · `list_documents` · `read_document` | 主力。`search_knowledge` 支持 hybrid / semantic / keyword 三种模式 |
| 问答 | `ask` | 跑端点指定 Agent，返回**带引用**的完整回答 |
| Wiki | `wiki_search` · `wiki_read_page` · `wiki_index` | 知识库开了 Wiki 才生效 |
| 写入 | `add_document` · `update_document` · `delete_document` | **默认关闭，建议保持关闭** |

### 装完能做到

- 「我和某人的关系是怎么变化的？」→ 跨 450 篇人物档案综合回答**并附引用**
- 「我 2026 年的情感线梳理」→ 基于事件库推理
- 「这个决定和我以前的记录有没有冲突？」→ 跨笔记一致性检查

## ② P0 · 博查 Bocha 联网搜索（中文最强）

### 为什么选博查

| 维度 | 博查 |
|---|---|
| 身份 | **DeepSeek 官方联网搜索供应商**；阿里 / 腾讯 / 字节官方推荐 |
| 覆盖率 | 国内 **60%+** AI 应用在用 |
| 中文效果 | 专为中文优化，无广告、语义排序 |
| 响应 | **0.15–0.3 秒**，1000–2000 QPS |
| 数据合规 | **数据不出境**，符合国内合规要求 |
| 价格 | **免费 2000 次**（1000 领取 + 口令「博查搜索」再兑 1000）→ 之后 **3.6 元/千次**（Bing 的 1/3） |

### 安装

官方 MCP：`BochaAI/bocha-search-mcp`（Python + uv）

```json
{
  "mcpServers": {
    "bocha-search": {
      "command": "uv",
      "args": ["--directory", "C:/Users/wardc/.workbuddy-ai/mcp-servers/bocha-search-mcp", "run", "bocha-search-mcp"],
      "env": { "BOCHA_API_KEY": "sk-xxxxxxxx" }
    }
  }
}
```

**API Key 获取**：访问 `open.bochaai.com` 注册 → 后台创建 Key（`sk-` 开头）
**免费额度**：首页 → 购买资源包 → 领「免费试用」；再点「兑换」输口令 **`博查搜索`**

### 工具

| 工具 | 能力 |
|---|---|
| `Bocha Web Search` | 全网搜索，返回标题 / URL / 摘要 / 站点 / 发布时间 / 图片；`count` 最多 50 条 |
| `Bocha AI Search` | 在 Web Search 基础上额外返回**结构化模态卡**（天气 / 日历 / 百科等） |

`freshness` 支持：`oneDay` / `oneWeek` / `oneMonth` / `oneYear` / 具体日期区间。

> 💡 **注意**：WeKnora 内置联网搜索**也支持博查**（另有 Serply、Brave，且 Brave/Serply 支持地区与时效过滤）。所以如果你主要用 WeKnora 问答，可以不单独装；但**想在 WorkBuddy 对话里联网，就得单独装这个**。

## ④ 不建议装（省得白折腾）

| 想法 | 判断 | 原因 |
|---|---|---|
| **Chrome DevTools MCP** | ❌ | 给前端调试用的，你不做前端 |
| **Playwright MCP** | ❌ | 你已有 `agent-browser` + `playwright-cli` 技能，**功能重复** |
| 继续堆 MCP 到 10+ 个 | ❌ | 官方共识：4–6 个上限。多了模型选错工具、烧 token |
| 已归档的包（`server-github` / `server-brave-search` 等） | ❌ | **2025-05-29 已归档**，网上大量教程仍在教，装不上或无人维护 |

## ⑤ 一个绕开 Docker 的替代方案：LightRAG（评估后：不推荐）

联网搜到一条**看起来能绕开你 Docker 卡点**的路：LightRAG 可以 **Windows 原生跑，不装 Docker、不碰 WSL**。

**但实测评估后不推荐**，理由如下：

| 项 | 情况 |
|---|---|
| 包名 | `lightrag-hku`（不是 `lightrag`），需 **Python 3.10**（3.13 装 faiss-cpu 会编译失败） |
| 硬件门槛 | CPU 需 **AVX2** ✅ 你 12 代 Intel 满足；内存**最低 16GB** ⚠️ 你 15.7GB **刚好卡线**，且只剩 5.3GB 可用 |
| 致命问题 | 486 篇文档的**图抽取要逐篇调 LLM**。本地 7B 在 CPU 上每秒几个字，**跑完要几天** |
| 补救 | 抽取改用 DeepSeek API（快、便宜）+ 向量化用本地 `nomic-embed-text`（你已有） |
| 但 | **WeKnora 功能更全**（界面、Wiki、多数据源、MCP、钉钉/Confluence 接入），且你**已经部署好了** |
| 结论 | ❌ **与 WeKnora 重复，不建议再搭一套** |

> 唯一值得借鉴的点：LightRAG 的 **hybrid 检索（局部子图 + 全局归纳）** 思路比纯向量检索强。WeKnora 本身也支持混合检索 + 重排，能力不输。
