## 二、✅ 能部署 & 建议部署

### A. MCP Server（最该做的，全是轻量）

> ⚠️ **先记住一条**：官方那批老包（`server-github`、`server-postgres`、`server-brave-search`、`server-slack`）**2025-05-29 已归档，不再维护**。网上大量教程还在教 `npx @modelcontextprotocol/server-github`，**已经失效**。
> 官方**仍在维护**的参考实现只有：`Everything / Fetch / Filesystem / Git / Memory / Sequential Thinking / Time`。
> **装 4–6 个就够，不要贪多**（每个 Server 的工具描述都吃上下文，装多了模型会选错工具）。

**按你的实际需求排序**：

| 优先 | MCP | 作用 | 安装 |
|---|---|---|---|
| ⭐⭐⭐ | **DBHub** | 让 AI 直接查你的 **SQLite**（微信索引、分析库） | `npx -y @bytebase/dbhub --dsn "sqlite:.../index.sqlite"` |
| ⭐⭐⭐ | **Filesystem** | 受控读写指定目录 | `npx -y @modelcontextprotocol/server-filesystem <路径>` |
| ⭐⭐⭐ | **Context7** | 治「按两年前的 API 写代码」 | `npx -y @upstash/context7-mcp` |
| ⭐⭐ | **Fetch** | 抓网页转 Markdown 喂模型 | `uvx mcp-server-fetch` |
| ⭐⭐ | **Memory** | 跨会话长期记忆（知识图谱式） | `npx -y @modelcontextprotocol/server-memory` |
| ⭐⭐ | **Git** | 本地仓库 diff/log/blame | `uvx mcp-server-git --repository <路径>` |
| ⭐ | **Sequential Thinking** | 复杂问题显式分步推理 | `npx -y @modelcontextprotocol/server-sequential-thinking` |
| ⭐ | **Playwright MCP** | 让 AI 真开浏览器验证前端 | `npx @playwright/mcp@latest` |
| ⭐ | **Chrome DevTools MCP** | 控制台报错/网络/性能面板 | `npx chrome-devtools-mcp@latest` |

**💡 对你最值的一个是 DBHub**：你有 `wechat-mcp/index.sqlite`（33.7 万条）和 `wechat-analysis-scale.sqlite3`。装上 DBHub，Agent 就能**直接用 SQL 查你的微信数据**，比现在自建的 3 个固定工具灵活得多。

**⚠️ DBHub 安全铁律**：只给**只读**连接，别把写权限交给会自己决定执行什么 SQL 的 Agent。

### B. 本地小模型兜底（可选，能跑但不强）

**4GB 显存实测能跑的**（来自 2026 本地部署实测）：

| 模型 | 量化 | 显存占用 | 场景 |
|---|---|---|---|
| **Phi-4 3.8B** | Q4_K_M | ~2.8 GB | 简单问答、英文写作 |
| **Gemma 3 4B** | Q4_K_M | ~3.2 GB | 轻量对话、摘要 |
| **Qwen3 4B** | Q4_K_M | ~3.0 GB | 中文问答、翻译 |

**现实**：4GB 配置**响应速度 3–5 tokens/s**，还会有理解偏差。官方建议是「4GB 配置先试试免费云端额度，比本地跑 4B 体验好得多」。

**但你有磁盘问题**：每个模型要 3GB+，而你**只剩 18.5GB**。装 2 个就占 6–7GB。

> **建议**：只装 **Qwen3 4B Q4（~3GB）** 一个，作为**断网兜底**（你已有 Ollama 习惯）。别多装。

### C. 不部署、直接用（最省事）

| 需求 | 方案 | 理由 |
|---|---|---|
| 联网搜索 | 现成云端 API / 免费额度 | 本地跑不动 |
| 大模型推理 | DeepSeek / GLM-5.3 / 小米 MiMo | 你已有额度，API 便宜 |
| 图像生成 | 即梦 / Nano Banana（在用） | FLUX 本地要 12GB+ 显存 |

## 三、⚠️ 能装但没必要

| 项目 | 为什么不建议 |
|---|---|
| **Open WebUI**（145K star） | Docker 镜像几个 GB + 常驻内存，你只剩 5.3GB 可用内存 |
| **Tabby**（自托管 Copilot） | 需要跑模型，4GB 显存撑不住 |
| **vLLM** | 对 Windows 不友好，且需大显存 |
| **WeKnora 完整版** | Docker Compose 多容器，磁盘扛不住（但 **Lite 单二进制版可以考虑**，见下） |

> 💡 **例外**：WeKnora 的 **Lite 单二进制版**（SQLite + 内存队列、无外部依赖）理论上能跑，但**磁盘 18.5GB 依然危险**——先清理再谈。

## 五、前置问题：磁盘必须先解决

**C 盘只剩 18.5 GB，这是部署任何东西的第一道墙。**

你自己的 [[磁盘梳理与清理方案]] 已经算过：**能腾出 120GB+**（其中 63GB 纯垃圾 + 57GB 可搬走冷数据）。

**建议顺序**：
1. **先清理**（按那份方案执行）→ 腾出空间
2. **再部署**（MCP 是几 MB，不受影响；但任何 Docker / 模型都需要空间）

> MCP Server 本身几乎不占空间，**现在就能装**，不必等清理。
