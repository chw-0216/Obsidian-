## 八、★ 自我模型层（2026-10-10 新增 · **仅本地，不得对外**）

> **它解决什么**：现有各层能回答「他是什么样的人」「他和谁什么关系」，
> **但回答不了「他为什么在这个时刻这样选」** —— 而后者**无法从行为里推出来**。

**位置**：

| 对象 | 路径 |
|---|---|
| 数据 | `工作区\analysis.sqlite` → `self_claims` / `claim_evidence` / `choice_episodes` / `understanding_views` / `learning_questions` / **`recommendations`** / **`rec_deps`** / **`predictions`** |
| 视图 | `Obsidian Vault\06_自我模型\`（**6 篇**，**自动生成，勿手改正文**） |
| 脚本 | `工作区\tools\selfmodel.py`（`init` / `import` / `render` / `stats` / `list` / `answer` / `review` / `reassess` / `outcome` / `stale` / `recimport` / `rec` / `link` / `impact` / `brief` / `changes` / `verify` / `reason` / `sync` / **`predict`** / **`calibrate`** —— 共 **21 个**子命令） |

**★ 依赖链（2026-10-10 下午新增 · 第二轮）**

> 61 节把「哪条建议因此改变」**写进了视图，但没有东西在计算它**。第二轮补上机制。

| 表 | 作用 |
|---|---|
| `recommendations` | 建议清单 · ★ 灵魂字段 **`impact_if_wrong`**（这条建议赖以成立的理解若错了，后果是什么） |
| `rec_deps` | 建议 ← 理解 的依赖关系（`dep_kind`：假定 / 需要 / 依据） |

**三个必须知道的读取入口**：

```bash
python tools/selfmodel.py brief "<当前问题关键词>"   # ★ 按问题取「阅读包」：相关理解+依据+反例+未知+依赖的建议+相关选择
python tools/selfmodel.py impact <claim_id>          # 这条理解被改，会动到哪些建议
python tools/selfmodel.py changes [--since DATE]     # 变化清单 + 受影响的建议
```

**★ 手填区与回写闭环（2026-10-10 晚 · 第三轮）**

> 修复的是方案里的 `synchronization_gap`：`render` 会**重写**视图，所以「你在 Obsidian 里填的东西」原先**根本没有回路**——
> 填了也会被下一次 render 覆盖。核心闭环「**围绕一次真实选择，补上你的理由**」因此是断的。

| 环节 | 做法 |
|---|---|
| **在哪填** | 三个视图末尾的 **`## ✍️ 手填区`**（`我的选择与理由` / `值得继续问的问题` / `系统当前怎样理解我`）。写法：`[ID]` 一行，下面 `字段: 内容`；**空行不写入** |
| **字段名** | 选择：`理由` / `实际选择` / `仍会这样选` · 问题：`回答` · 理解：`我的判断`（认可 / 需要修正 / 不认同 / 不适用于这件事）+ `备注` |
| **怎么生效** | `python tools/selfmodel.py sync --apply`（或 `tools\sync_from_vault.py --apply`）；**直接跑 `render` 也会先自动读回** |
| **安全** | 默认只读 · 写前自动备份整库 · 每次改动记 `revisions` · 值不合法**跳过并报警**且该行**保留**在手填区 |
| **永不失手** | 已入库的行下次自动从手填区消失；**没入库的（写失败）一定保留** |

**★ 已自检**：`_tmp\test_selfmodel_sync.py` 在**数据库副本**上跑 7 个用例（填理由入库 / 幂等 / render 读回 / 非法值保留 / 答题改状态 / `reason` 直写 / **render 幂等**）→ **7/7 通过**，真库不受影响。

**★ 理解判断与校准（2026-10-11 新增 · 第四轮）**

> 《长期个性化智能体》第三节要求**同时回答两件事**：
> ① **理解判断**：在当前条件下，**我推测你会怎样选**，依据是什么。
> ② **决策建议**：结合你的目标、资产和机会，**我建议怎样选**，代价是什么。
> 第四轮之前，系统**只会做②**（`recommendations`），**不会做①**；且 `outcome` / `user_reassessment` 填了**不回流任何东西**（死数据）。

| 表 | 作用 |
|---|---|
| `predictions` | **①理解判断**：`predicted_choice` / `predicted_reason` / **`basis_claims`（必须能回链 `self_claims`）** / `alt_choices` / `confidence` ＋ `linked_rec_id`（关联②建议）＋ 实际回填 ＋ 对照（`match_status` / `match_by`）＋ 结果（`outcome_verdict`） |

```bash
python tools/selfmodel.py predict add P-XXX "待决问题" "系统推测他会怎么选" --basis SC-XXX
python tools/selfmodel.py predict resolve <id> "实际选择" "他的理由" [--match matched|partial|mismatched]
python tools/selfmodel.py predict outcome <id> worked|failed|mixed "说明"
python tools/selfmodel.py calibrate     # 命中率 + 按依据类型分组（哪类理解更准/更不准）
```
→ `brief` 阅读包里**预测与建议并列**；视图 6 = `06_自我模型\理解判断与校准.md`。
→ ★ **`resolve` 判为不一致时，会自动列出「哪条依据需要复核」** —— 这是「从结果中学习」的落点。

**★ 任何 harness 读取本层时必须遵守**：

1. **本人表述 ≠ 系统推断 ≠ 外部核实** —— 三者分列字段，**不得混写**。
2. **老师/第三人的要求**只作为**对应项目条件**保存，**不得**写成本人偏好。
3. **`human_review` 与 `answer_verbatim` 不可由模型写入** —— 本人审核不可伪造。
4. **「可行选项」≠「他想要的」** —— 能做不等于想做。
5. **缺少检索结果标「覆盖缺口」**，不得写成「现实不存在」。
6. **模拟方案不得写进「实际结果」字段**。
7. **`SC-MECH-002` 红线**：「证明有用」**已从总解释降级为有条件假设** —— 引用时必须带适用边界。
8. **建议不得比它依赖的理解更确定** —— 依赖不稳（`disputed` / `withdrawn` / `superseded` / `needs_verification` 或 `corrected` / `rejected` / `not_applicable`）的建议**必须标红**，不得照常给出。
9. **纠正一条理解 ≠ 自动改掉建议** —— 系统只**标出需要重审**，改不改由本人定。
10. **`verify` 只跑 DB 副本** —— 不得在真库上做假设性纠正。
11. ⚠️ **本层默认 `privacy_scope='private'`，与 §七 公考隔离区不互通** —— 本层内容**不得**交给外部 AI。
12. ★ **不得绕过手填区直接改视图正文** —— 正文由 `render` 重写，改了必被覆盖；**要改就改手填区**（或走 CLI `reason` / `answer` / `review`）。

15. ★ **实际选择与本人理由必须本人回填后才算校准** —— **不得用系统推测冒充本人理由**；`match_by='auto'` 的粗判**必须标明来源**，不得当人工判定用。
