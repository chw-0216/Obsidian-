# 字段与状态规范

适用于新建人工笔记与后续试点。既有笔记、ID、数据库字段和生成器保持原状；本规范不表示已完成全库迁移。规范建立日期不代表资料核验日期。

## 身份与版本

| 字段 | 用法 |
|---|---|
| `id` | 对象稳定标识；已有 EVT、CON、SC、REC、决策与预测ID原样保留。新对象先留空，统一登记确认唯一后分配，不由姓名猜身份 |
| `type` | 对象类型：人物、项目、事件、结论、资料、目标、行动、决策；规范、模板、入口是文档类型 |
| `note_role` | 主档、专题报告、历史快照、索引、模板等用途；人物专题报告不等于新增人物 |
| `aliases` | 已确认别名列表；不能凭相似姓名自动合并 |
| `schema_version` | 本规范版本为1；与原有生成器版本、事实修订版本分开 |
| `maintainer` | 人工、脚本或混合；脚本页另记 `generated_by` 和人工区边界 |

已有文件先不改名。新常青页使用稳定名称，快照使用 `YYYY-MM-DD_主题`。身份、当前状态与长段推断不塞进文件名。`id` 属性不自动保证短ID链接可跳转，使用实际路径链接并把ID作为显示名。

## 时间分开记录

| 字段 | 含义 |
|---|---|
| `created` / `updated` | 本笔记建立／修改日期，不能代替事件日期 |
| `event_date` | 事件发生日期；既有事件的 `date` 保留，迁移时再映射 |
| `as_of` | 信息覆盖截至日期，不因今天编辑就改成今天 |
| `verified_at` | 实际核验日期；没核验就留空 |
| `due` | 已确认期限；相对时间需结合原始消息日期解析 |
| `review_after` | 下次复核时间，非完成期限 |
| `completed_at` | 有依据的完成时间；只知已完成、不知哪天时，时间仍留空 |

日期用 `YYYY-MM-DD`，需要时刻时记录带时区的时间。保留旧 `expires`；过期表示需复核，不表示现实任务取消。

## 状态分轴

| 轴 | 新人工笔记建议值 | 注意 |
|---|---|---|
| `epistemic_status` | 原始记录、本人报告、有证据支持、推断、待核验、已被修正 | 知识可信状态；有记录不代表记录内容必然真实 |
| `action_state` | 待澄清、可执行、等待、进行中、完成、取消 | 行动执行状态；必须有结果证据或本人确认才记完成 |
| `lifecycle` | 当前、历史、被替代 | 历史不等于错误；被替代需指向新版本 |

旧 `status`、`verdict`、`review_status`、`need_confirm` 等保持原值。本批不改其含义或生成器。不得把“有效结论”映射成“已执行行动”。人工判断、证据质量和执行状态各自记录。

## 最少必需与可选扩展

新人工对象记录类型、维护责任、来源与截至时间；未知字段保持空值。新ID只在登记后填写。关系用列表，未知关系用空列表，不放虚构链接。

行动至少写清做什么、何时算完成、当前状态依据。资源字段 `effort_minutes`、`energy_required`、`context`、`cost_estimate` 可选，由本人或具体执行估计补齐，不从人格推断。优先级由本人目标、硬期限和依赖约束共同确定，不自动继承旧文中的P0。

未知不等于0；未查到不等于不存在；未见完成记录不等于一定没做。凭据、验证码、证件号码不进入这些模板。
