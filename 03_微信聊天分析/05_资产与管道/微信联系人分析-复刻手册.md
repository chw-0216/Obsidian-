# 微信联系人分析 · 复刻手册

> **用途**：把「笑一」那套流程，**复刻到任意微信联系人**（恋人 / 家人 / 同事 / 客户 / 朋友）。
> 相关：[[WeFlow更新部署方案]] · [[分析流水线]] · [[笑一-唤醒协议与协同流程]] · [[笑一-互动复盘模板与动作库]]

## 〇、总览：四层架构

```
┌─ ① 数据层 ─────────────────────────────────┐
│  微信加密库 → WeFlow(解密) → JSON / SQLite   │
│  脚本：sync_weflow.py（增量）· live.py（实时）│
│        dbhub-wechat（全量 SQL，只读）        │
└────────────────────────────────────────────┘
              ↓
┌─ ② 分析层 ─────────────────────────────────┐
│  通用指标 + 通用框架（三态/称呼/四视图）      │
│  ✚ 专属层（每人重做：档案/事件/称呼语义）     │
└────────────────────────────────────────────┘
              ↓
┌─ ③ 行动层 ─────────────────────────────────┐
│  唤醒协议（喊一声出建议）· 复盘五问 · 欠账清单 │
└────────────────────────────────────────────┘
              ↓
┌─ ④ 工具层（可选并行）──────────────────────┐
│  Jev 实时副驾（秒级意图+危险等级+候选回复）   │
└────────────────────────────────────────────┘
```

**核心原则**：**通用层直接复刻，专属层每人重做。** 分不清这两层，复刻就会跑偏。

**朋友圈**：`GET /api/v1/sns/timeline?usernames=<wxid>&limit=200`
（全库上限 200 条；图片常 502，但**评论/点赞可读**——评论里常藏关键互动）

**实测（李梓燏，2026-09-27）**：

| 线索 | 发现 | 修正了什么 |
|---|---|---|
| 群昵称 | 「李梓燏-**建筑学院**」 | 此前误判"同院同学" → 实为**跨院** |
| 发言量 | 400 人大群 **0 条** / 7 人小群 **39 条** | 判定**场景型人格** |

## 三、分析层

### 3.1 通用指标（**任何人**都算这 6 个）

| 指标 | 算法 | 含义 |
|---|---|---|
| **字数比** | 我方平均字数 ÷ 对方平均字数 | 1.0 = 对等（健康）；>2 = 我在追 |
| **对方主动发起率** | 对方发起的对话轮数 ÷ 总轮数 | >50% = 对方有余力 |
| **响应延迟中位** | 对方回复我方消息的时间差中位数 | <1 分钟 = 在意 |
| **称呼密度** | 各称呼词频 ÷ 总条数 | 见 3.2 称呼字典 |
| **静默时长** | now − 最后一条消息时间 | >48h = 预警 |
| **谁收尾** | 最后一条消息的发送方 | 对方收尾 = 有安全感 |

### 3.2 通用框架（跨人可复用）

| 框架 | 内容 | 位置 |
|---|---|---|
| **三态诊断** | 🟢 绿（享受）/ 🟡 黄（Fawn 讨好）/ 🔴 红（Freeze 断连） | `04_方法论\三态诊断.md` |
| **称呼字典** | 老公=安全✅ / 宝贝=照顾者⚠️ / 无称呼=冻结🛑 | `04_方法论\称呼字典.md`（**每人语义需重标**） |
| **四视图** | 宏观（事情全景）/ 中观（事件）/ 微观（动作流）/ 关系（人物） | `04_方法论` |
| **双轨模型** | 情感轨（安全感）+ 现实轨（抗沉没能力） | 笑一专属，可推广 |
| **亲密动力学公式** | **安全 → 余力 → 欲望 → 给予**（顺序不能倒） | [[笑一-亲密动力学_欲望与给予的恢复路径]] |
| **零承诺原则** | 用已完成的行动给确定性，不用未来的承诺 | 通用沟通原则 |
| **复盘五问** | 见 [[笑一-互动复盘模板与动作库]] §1 | 通用 |

### 3.3 专属层（**每人必须重做**，不能套用）

| 专属项 | 说明 | 为什么不能套用 |
|---|---|---|
| **人物档案** | 关系性质、背景、家庭、职业 | 每人不同 |
| **创伤史 / 敏感点** | 什么话题会触发防御 | **这是最关键的一项** |
| **称呼语义** | 同一句"宝贝"，不同人含义不同 | 必须实测归纳 |
| **事件库** | 关系中的关键节点（引爆点 / 修复点 / 跃迁点） | 每人一条时间线 |
| **场景话术** | 具体场景怎么回 | 依赖上面四项 |

> ⚠️ **复刻失败最常见的原因**：把笑一的专属层（恐惧-回避型、零承诺、反嫌弃铁律）**直接套到别人身上**。
> **通用层照搬，专属层重做。**

## 七、五类联系人的适配差异

| 类型 | 核心目标 | 关键指标侧重 | 主要风险 |
|---|---|---|---|
| **恋人** | 安全感 + 欲望 + 给予 | 称呼、字数比、主动率 | 断连（Freeze）、Fawn 累积 |
| **家人（父母）** | 稳定在场、不索取 | 联系频率、事务/情感比 | 只当"事务通知"（如母亲 142 条 ≠ 关系淡） |
| **同事 / 上级** | 可靠 + 边界 | 响应及时性、闭环率 | 越界、情绪化 |
| **客户 / 商务** | 信任 + 推进 | 承诺兑现率、跟进节奏 | **过度承诺**（此处"零承诺"不适用，改"只承诺能兑现的"） |
| **朋友** | 长期低维护 | 主动率、间隔 | 单向消耗（只你找对方） |

> ⚠️ **零承诺原则不是万能的**：对**商务/客户**场景，适度承诺是必要的。
> 该原则的真正含义是「**只承诺你能兑现的**」，而不是"永不承诺"。

## 八、扩展：Jev 实时副驾（可并行使用）

### 8.1 Jev 是什么

**开源、非侵入式实时对话副驾**（Android / Windows / macOS 三端）。

**核心机制（和一般 AI 回复工具的根本差别）**：
> **判断模型不写字，只在固定选项里选。** 一次请求问 **7 道题**，约 1 秒出结果，**带概率和把握度**：
> ① 真实意图 ② **危险等级 0–9** ③ 对方要什么 ④ 该不该马上回 ⑤ 下一步怎么做 ⑥ 话里有没有话 ⑦ 紧张缓和了没

回复另由生成模型起草 **3 条候选 + 「暂不回应」**，再由 Jev 排序。**从不自动发送**，只填入输入框。

**Windows 版**（`yushen100/wechat-jev-assistant`，v0.3.0）：
- 读**当前微信会话的本地数据库**（只读桥接）+ UIA 识别标题，`Ctrl+Alt+J` 触发
- 输出：**对话阶段 / 需求 / 意图 / 紧张程度 / 建议动作 / 回答复盘**
- 本地历史 **AES-GCM 加密**
- 可选 100/150/200/250 条分析档位

### 8.2 能同时用吗 —— **能，强互补**

| 维度 | **Jev** | **本体系（WeFlow + 分析层）** |
|---|---|---|
| 时间尺度 | **秒级**（当前会话最近 10–250 条） | 全量历史（5,858 → 33.7 万条） |
| 触发 | `Ctrl+Alt+J` / 悬浮球 | 喊「唤醒」 |
| 输出 | 意图 + **危险等级 0–9** + 3 条候选 | 关系模型 + 长期策略 + 行动方案 |
| 优势 | **即时、在聊天窗口旁边** | **深度、跨会话、依恋模型、事件库** |
| 知识 | 本地笔记 + 联系人档案 | 完整人物档案 + 亲密动力学 + 动作库 |

**两者数据源一致**（都读本地微信库），所以**不冲突，可并行**。

### 8.3 四个互补接口（真正的价值）

| # | 互补点 | 怎么做 |
|---|---|---|
| **1** | **危险等级 0–9 ⇄ 三态诊断** | 两个**独立体系互相验证**。Jev 报 7/9 偏危险，我这边应同步显示 🟡 或 🔴；**不一致时就是最有价值的信号** |
| **2** | Jev「下一步怎么做」⇄ 我的红线 | Jev 的 7 个选项（翻记录/先道歉/给承诺/解释/接住情绪/少说两句/定安排）可做**交叉检查** |
| **3** | **我的档案 → Jev 知识库** | 把人物档案（依恋类型/敏感点/称呼语义）写进 Jev 的「知识库 + 联系人档案」→ 它的候选回复就带上语境 |
| **4** | **Jev 判断记录 → 我的复盘** | Jev 有加密历史库，若能导出，就是**逐条判断数据** → 可做长期趋势分析（危险等级随时间变化曲线） |

### 8.4 ⚠️ 一个必须注意的冲突

**Jev 的「下一步怎么做」里有「给承诺」选项 —— 这与笑一场景的「零承诺原则」直接冲突。**

**解法**：在 Jev 的**知识库/联系人档案**里明确写：

```
【沟通铁律】禁止使用「给承诺」类建议。
理由：对方父亲破产前"说过很多话"，她信行动不信语言。
替代：把承诺换成"已完成的行动"或"当下可交付的东西"。
```

**这一步不做，Jev 会持续给出违反铁律的候选回复。**

### 8.5 隐私：**可以做到全本地**（重要）

Jev 会把脱敏后的对话发给**你配置的接口**（默认 OpenRouter / TypeSafe / DeepSeek）。

> ⚠️ **这与你的「数据主权、本地处理」原则冲突。**

**但它支持「任意 OpenAI 兼容地址」→ 可以直接指向本机 Ollama：**

```
设置 → 接口
  判断接口：http://127.0.0.1:11434/v1   （模型按本地可用能力选）
  回复接口：http://127.0.0.1:11434/v1
  API Key ：ollama（占位）
```

**Ollama + Jev = 零外发**。代价是判断质量下降（Jev 判断模型为英文训练，中文场景本就有波动；本地小模型会更弱）。

**建议**：**起草用本地，判断用云端**（判断只需 7 个选择题 + 概率，信息量小；起草要发最近 30 条，信息量大）。

### 8.6 已知局限（官方自述）

- Jev **主要用英文训练，中文判断质量会波动**；题目按**亲密关系冲突场景**校准，**群聊/工作场景准确度下降**
- 群聊按一对一分析，多人交叉对话会不准
- 给的是**概率不是结论**
- 国产 ROM 后台冻结会让悬浮球消失（需开自启动 + 省电无限制）
- OCR 只认屏幕可见部分，长消息会被截断

## 九、踩坑表

| 坑 | 症状 | 解法 |
|---|---|---|
| **代理拦截** | `os error 10061 积极拒绝`（像 WeFlow 没开） | 清 `http_proxy` / curl 加 `--noproxy '*'` |
| **水位语义** | 漏消息 | 水位 = **最后一条消息 timestamp**，不是 `sync.watermark` |
| **字段名** | 发送方判反 | 用 `sender`（=wxid），**不是 `isSender`** |
| **WeFlow -105** | 启动报错 | 关 WeFlow → 重命名三处 Runtime 目录 → 重启 |
| **端口占用** | 5031 被占 | `netstat -ano \| findstr :5031` |
| **dbhub 索引过期** | 查不到新消息 | 跑 `刷新微信索引.cmd`（快照机制） |
| **npx 缓存损坏** | DBHub 报 SyntaxError 但文件正常 | 清 `npm-cache\_npx\<hash>` |
| **DBHub 参数** | 启动失败 | **必须等号形式** `--config=<path>` |
