你列的四个项目本质上是**同一件事的四种封装**：「把微信当成 Agent 的消息出入口」。

### ⚠️ 坏消息：三个硬约束

**约束 1 — WeFlow 是「只读导出器」，不是发送器**

我对 `app.asar`（497 MB）做了字符串分析：

```
/api/chat 186    ← AI 对话界面，不是微信 API
/api/messages 9  ← 读消息
sendMessage 287  ← 全是 AI SDK 内部（ui/message 协议），与微信无关
/api/send : 0    ← 没有发送端点
```

疑似发送能力的关键词，逐一验伪：

| 关键词 | 命中 | 真相 |
|---|---|---|
| `发送消息` | 6 | 全是**统计卡片**文案（"发送消息的人数"），不是功能 |
| `sentMessages` | — | 统计"你历史上发出多少条"（`stat-card`） |
| `private_outbound_people` | — | KPI 指标名 |
| `msg_send` | 6 | **SQL 列名**（`last_msg_sender`），不是动作 |
| `MsgSend` | 16 | 消息结构字段 |

**结论：WeFlow 没有对外 HTTP 发送接口，也没有发送动作。** 你上轮跑通的 4,494 个会话全靠它**导出**——它是数据管道，不是消息通道。

**约束 2 — 发送必须走 iLink 协议，而这是最有风险的一环**

`ilink/` 目录里有 `netbridge`、`kvcomm`、`wechat` 三个子目录，说明新版微信 4.x 的收发链路是 **iLink 长连接协议**。你列的 `wechatbot` 说"直连 iLink 底层"——**它需要逆向这套协议**，而这套协议：
- 随微信版本升级会变（你桌面就有 `lock-weixin-update.ps1` 在锁版本，说明你自己也怕它变）
- 一旦触发风控 = **账号封禁**

**约束 3 — 你的账号是高价值账号，不能拿来试错**

你的聊天记录库里：导师（陈晔）、学生（关宇佳）、合作方（韩云峰）、家人、情感线（笑一/沐茜妍/陈昶文）、欠钱关系（舒泽林/郑英泽）——**6,275 条的陈昶文、6,691 条的导**。这不是小号。

⚠️ **任何自动发送功能，我都强烈建议你只在自己建的"测试群/文件传输助手"里先跑**，不要直接接真实联系人。

## 四、我建议的方案：自建最小可用 Bridge（不装任何一个）

### 为什么自建

1. **不要 fifth AI backend**——你有 DeepSeek-v4-pro 自建端点 + LiteLLM 中转，任何内置 AI 回复都是降级。
2. **不要第四套协议实现**——WeFlow 已经在解析 iLink 数据了，再加 wechatbot = 两套解析同时写、互相破坏。
3. **你的真实需求是"三合一"**：WeFlow（读）+ Agent 后端（想）+ 极小的发送通道（写）。

### 三段式架构（按风险从低到高落地）

#### 🟢 第一段：立刻可做，零风险（1-2 小时）

**「微信内容 → Agent 分析 → 结果落文件」闭环**

你上轮已经把这条链跳了 90%：
```
WeFlow 导出 → 472 人画像 / 6,303 片段标注 / 人物案例库
```

缺的最后一环是**自动触发**：新消息来了 → 自动增量分析 → 输出到你的归档区。

**具体做法**：
- 用 WeFlow 的 `data-cache` 或直接扫 `xwechat` 的 db 变化（mtime）
- 检测到新消息 → 调用你已有的 DeepSeek-v4-pro 端点做增量分析
- 结果追加到 `ChatArchive/03_reviews/`

**这一步不需要任何发送能力，零封号风险，纯增量价值。**

#### 🟡 第二段：可行但有工作量（半天-1 天）

**「方向 A：只读遥控」——微信只看结果，不发送**

这是最聪明的折中：**用微信发指令，但回复走别处**。

- 你手机上给「文件传输助手」发 `/analyze 陈昶文`
- 电脑端监听该消息（WeFlow 能读）→ 触发 Agent → 结果写回**同一个文件传输助手**（这条是发给自己的，不算骚扰）

⚠️ 注意：即使发给自己的"文件传输助手"，**发送动作本身仍需 iLink 写协议**。如果不想碰协议，可降级为：**结果写到本地 md，微信只作为"指令入口"读取**。

#### 🔴 第三段：高风险，建议缓做

**「双向主动推送」**——真正在微信里收发 Agent 消息。

**要碰 iLink 写协议，这是唯一有封号风险的环节。**

**如果一定要做，我建议的顺序**：
1. 先只在一台**备用/测试微信号**上验证发送
2. 严格限频（≥30 秒/条，人类化间隔）
3. 只在白名单会话（自己的号 + 一个测试群）
4. 保留 kill switch（`lock-weixin-update.ps1` 那套经验正好用上）
