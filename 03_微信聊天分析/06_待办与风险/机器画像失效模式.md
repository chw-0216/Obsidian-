# ⚠️ 机器画像失效模式

> **每次批量分析前必读。** 这是已在真实数据上验证过的系统性缺陷。

## 缺陷：性别与关系性质被读反

**真实案例**：[[陈昶文]] 被机器判为「朋友 / 学弟」，实为 **大一学妹、暧昧追求中**。

| 维度 | 机器（❌） | 真实（✅） |
|---|---|---|
| 关系 | 朋友 | 大一学妹 |
| 性别 | 学弟/"他" | 女 |
| 性质 | 哥们情 | 暧昧·正在追 |

### 误判机制

```
模型识别到「学长—照顾者/后辈」结构
        ↓
默认这是同性友情
        ↓
全篇用"他/学弟"，从不做性别验证
```

## 缺陷 2：时间窗口截断 —— 把「进行中」判成「已结束」

**真实案例**：[[笑一]] 被机器判为「朋友 / 潜在恋人」（600 条 · 截至 2026-07-17），
实为 **现任女友**（5,625 条 · 持续至 2026-09-25 且仍在进行）。

| 维度 | 机器（❌） | 真实（✅） |
|---|---|---|
| 关系 | 朋友 / 潜在恋人 | **新女友（现任）** |
| 条数 | 600 | **5,625** |
| 时间跨度 | 截至 2026-07-17 | 2026-05-08 → **09-25（仍在持续）** |
| 性质 | 暧昧、不确定 | 已确立恋爱（称呼改「宝」）|

### 误判机制

```
分析窗口在 07-17 被截断
        ↓
只看到"关系升温但未确认"的那一段
        ↓
判成"暧昧 / 潜在恋人"，且不知后续已确立
```

> 与缺陷 1 的区别：缺陷 1 是**语义读反**（性别/关系性质），
> 缺陷 2 是**数据不完整**（窗口截断）—— 两者的共同后果都是"关系定性错误"。

### 防御

- **条数、时间戳一律回原始 JSON 核验**，不信机器自报的 totalCount
- 分析前确认**导出截止时间** ≥ 目标时间，否则结论只能标注为"阶段性"

## 缺陷 3：工具误报 —— 操作成功但报"失败"

**真实案例**：`clean_noise_groups.py --apply` 删除 554 个中文名目录时，
Windows 回收站 API（`SHFileOperationW`）对**中文/emoji 路径**返回 `WinError 2 系统找不到指定的文件`，
脚本打印 **「成功 0，失败 554」**——但目录**实际已全部被移走**。

### 误报机制

`SHFileOperationW` 的 `pFrom` 需要 **双空终止符** `path + "\0\0"`；
含宽字符（中文/emoji）时返回值不可靠，**不代表操作真实结果**。

### 防御

- **不要信脚本的成败回显**，直接 `os.path.exists(target)` 核验
- 清理类操作**必须跑一次"清单 vs 现存"的差分核对**（本次即靠此发现 126 个"失败"全是误报）
- 大批量删除**分批 + 每批核验**，别一次跑完

```python
# 正确的核验方式
existed = sum(1 for r in checklist if os.path.exists(os.path.join(root, r['dir'])))
# existed == 0  → 真的删干净了，脚本回显的 "失败" 是假的
```

## 缺陷 4：锚点文件本身也会过期 ⚠️ 新发现

**真实案例**：`人际网络标注.csv` 是**人工标注的锚点**、被本页奉为"优先级高于机器"的真理来源——
**但它自己的 `Messages` 列却是过期的快照。**

| 人 | CSV 自报 | 实测 | 偏差 |
|---|---:|---:|---|
| [[笑一]] | 600 | **5,625** | **-89%** |
| [[陈昶文]] | 6,275 | 6,275（与机器画像 3,753 不一致） | 待核 |

### 误判机制

```
人工标注时（某一天）抄了当时的消息量
        ↓
此后关系继续增长，但 CSV 从未回源更新
        ↓
CSV 的「关系定性」仍然正确（人写的，不会变）
CSV 的「消息量」已经失真（数字会变）
```

> ⚠️ **与缺陷 1/2/3 的层级不同**：前三个是"机器错"，这是**"锚点错"**。
> 一旦锚点本身失真，**所有基于它的量级分析都是低估的**。

### 防御

- **锚点文件的定性列 → 可信，直接用**
- **锚点文件的数值列 → 必须回原始 JSON 重算，不可信**
- 每次分析前对数值列做一次**抽样回源核验**（至少抽 3 人）

## 缺陷 5：线下共存关系在微信数据里完全失真 ✅ 已确认

**确认案例**：[[母亲-刘丽萍]] 仅 142 条，在 53 人网络中排第 40 位左右。

> **本人确认（2026-09-26）：「我与父母平常住在一起」**

### 失真机制

```
同住 → 沟通在饭桌/客厅/日常场景完成
     → 微信只承担事务性通知（买东西、几点回、转文件）
     → 条数自然低，但关系强度极高
        ↓
把"低条数"读成"关系淡" → 结论完全反向
```

**这是所有渠道型数据集的通病**：微信只能测"微信里的关系"，测不了"物理共处的关系"。

### 防御（强制）

1. **建立「线下共存」标记** —— 同住者（父母）永久排除出消息量排序
2. 分析任何关系前先问：**"这条关系的主要沟通渠道是微信吗？"**
3. 家人/亲密关系单独成表，不参与"人均消息量"排名

### 影响面

- 家人类别"人均 328 排倒数第一" → **该结论作废**（指标对家人无意义）
- 已更正 [[情绪成本与关系熵]] 与 [[社交带宽分配]]

## 缺陷 6：消息量 ≠ 关系价值（结构性·方向性错误）⚠️

### 错误示范（本次自我纠正）

初版把 [[Eloise]]（4,686 条）列入"高投入负产出区"，判为"最大的可优化带宽"。

> **本人确认（2026-09-26）：「有隐性价值，毕竟工作不错可以考虑相处」**

**根因**：只做了**成本侧核算**（她索取），没做**收益侧核算**（她给得出职业网络）。
→ Eloise 在**核心央企**在职，对一个需要"稳定工作 + 职业路径"的人而言是**资产不是负担**。

### 铁律：双向核算

任何高消息量关系，必须过两道：

| 道 | 问什么 |
|---|---|
| 1. 成本侧 | 我付出多少条 / 多少时间？ |
| 2. **收益侧** | **这段关系能给出什么？（资源 / 信息 / 情绪 / 机会）** |

> ⚠️ **「她索取」不等于「这段关系亏」。**
> 只有「索取 **+ 无对价**」才等于亏。

### 计入负产出前必须先剔除的四类

| 类别 | 例 | 为什么不算亏 |
|---|---|---|
| 义务性 | 蔡黎明、蔡晓梅 | 不是"投入"，是"必须" |
| 有对价 | **Eloise** | 成本高但收益也高 |
| 渠道失真 | **父母（同住）** | 数字无意义 |
| 主动止损 | 077 | 是成功决策，不是亏损 |

**修正结果**：负产出区从 6,578 条 / 14.2% → **1,892 条 / 4.1%**（详见 [[高投入与负产出区]]）

## 结论

**机器模型有系统性捷径偏差，工具链也有沉默的误报。**
人工标注 > 机器输出；直接核验 > 脚本回显。
