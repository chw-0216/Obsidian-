# 微信 Agent 通道 · 大白话版

> 不讲技术，只讲「能做什么 / 不能做什么」

---

## 一句话总结

**能读，不能写。** 微信消息可以自动读出来分析，但「自动发消息」这条路几乎被堵死了。

---

## 一、先打三个比方

### 比方 1：WeFlow = 一个「只能复印，不能寄信」的秘书

你上轮让 WeFlow 导出了 4,494 个会话——那是它的本事。
但你想让它「帮我回条微信」？它做不到。我把它的程序文件（497 MB）翻了个底朝天：

| 我以为的功能 | 实际真相 |
|---|---|
| `/api/send` 发送接口 | **一次都没出现** |
| `sendMessage` 出现 287 次 | 全是它自己 AI 对话框的内部代码，跟微信没关系 |
| 中文「发送消息」出现 6 次 | 全是**统计卡片上的字**——比如"发送消息的人**数**：120" |
| `msg_send` 出现 6 次 | 是**数据库的列名**，不是动作 |

**结论：它是个数据搬运工，不是消息通道。**

### 比方 2：你的微信消息库 = 一个上了锁的保险箱

我在你电脑上找到了微信存消息的真身：

```
C:\Users\wardc\xwechat_files\wxid_zn4ozsnn8esr21_db45\db_storage\
├── message\message_1.db      （90 MB，正在实时写入）
├── message\message_fts.db    （2.35 GB！微信自己建的全文本索引）
├── session\session.db        （会话列表，刚刚 20:33 还在写）
└── contact\contact.db        （联系人）
```

**好消息**：文件是活的，微信每时每刻都在往里写（我发现 20:29、20:33 都有新写入）。

**坏消息**：**全加密了。** 我用数据库工具去开，它回我一句 `file is not a database`——就像你拿把普通钥匙去捅保险箱，捅不动。

所以：**想直接读微信库，要么拿钥匙（解密），要么用 WeFlow 这个"官方翻译官"。**

### 比方 3：iLink = 微信的「内部通话专线」

新版微信收发消息走的是 iLink 协议。你电脑上确实有这个目录（`ilink\netbridge`、`ilink\kvcomm`）。

`wechatbot` 那个项目敢号称"直连 iLink 底层"，本质是**去偷听这条专线怎么说话**。

**问题**：这条专线是加密的、会变版本（你自己都在用 `lock-weixin-update.ps1` 锁微信版本），而且——

**腾讯盯这个盯得很紧。偷接专线 = 大概率封号。**

## 二、那张图：什么能做，什么不能做

| 你想做的 | 能做吗 | 说明 |
|---|---|---|
| 把聊天记录导出来分析 | ✅ **早就做了** | 472 人画像、6,303 片段标注都跑完了 |
| 微信发条消息 → 自动分析并把结果写文件 | ✅ **能** | 中等工作量，零风险 |
| 微信里问 AI 问题 → 电脑自动回答 | 🟡 **半能** | 读没问题；"回答"要想办法绕开发送 |
| 让电脑主动给你微信发消息 | 🔴 **基本不能** | 必须破 iLink，**赌上封号风险** |
| 微信里收到 Agent 的实时推送 | 🔴 **同上** | 高价值账号，不值得赌 |

## 三、为什么「发消息」这么难

三道锁，一道比一道难：

**第一道锁：WeFlow 不会发**
→ 换个工具，或者自己写。**能绕开。**

**第二道锁：微信的消息库加密**
→ 消息都锁在保险箱里。你能通过 WeFlow 拿到复印件，但改不了原文。

**第三道锁：iLink 协议是私有的、会变、还被风控**
→ **这道绕不开，也是唯一有封号风险的。**

前两道是技术问题，第三道是**风险问题**。

## 四、你真正该做的（按推荐顺序）

### ⭐ 方案 A：让「新消息」自动触发分析（强烈推荐）

**做什么**：只要有新消息进来，电脑自动分析它，结果写进你的归档文件夹。

**用户体验**：
```
你在微信正常聊天（什么都不用做）
        ↓
电脑发现"有新消息了"
        ↓
自动调你那个 DeepSeek 分析
        ↓
结果自动存进 Desktop\07_聊天记录分析\
```

**优点**：**完全不碰发送**，所以**零封号风险**。而且你上轮已经把这条流水线跑了 90%，只差"自动触发"这一个开关。

**工程量**：半天。

### ⭐ 方案 B：微信当「遥控器」（推荐）

**做什么**：你在微信发 `/分析 陈昶文`，电脑去跑，跑完把结果放进一个文件。

**用户体验**：
```
你（手机）:  /分析 陈昶文
电脑        : 收到！开始跑……
电脑        : 跑完了，结果在 Desktop\...\陈昶文.md
```

**关键点**：**"读"是无风险的，"回"才有风险。** 所以先做"发指令"这一半，回复可以放在本地文件里看。

**工程量**：1 天。

### ⚠️ 方案 C：真正双向推送（不推荐现在做）

**做什么**：电脑主动给你微信发消息。

**只有这个要碰 iLink，也只有这个会封号。**

**如果非要做，我的底线建议**：
1. 先用**备用微信号**试，别用你的主号
2. 先只在**"文件传输助手"**（发给自己）里试
3. 严格限速（≥30 秒一条，别像机器人）
4. 保留一键停止

**你的账号值不值得赌？** 你自己判断——导师 6,691 条、学生、合作方、家人、三条情感线、三个欠钱关系都在这个号里。**我会说：不值。**

## 五、那四个开源项目，到底要不要装？

**答案：一个都别装。**

| 项目 | 为什么不用 |
|---|---|
| **WeChat-Bridge** | 内置了 5 家 AI 回复，你不需要（你有自建的 DeepSeek）。但它的**思路**可以抄 |
| **weclaw** | /cc /gm /oc 切换后端——**你电脑上三个快捷方式已经能做这事了**，多装一层就是多一个坏的地方 |
| **vibe-remote** | 一个好看的控制面板。好看≠有用 |
| **wechatbot** | 唯一补空白的（语音），但要破 iLink，**风险最大** |

**真正的问题不是"装哪个"，而是"你自己的零件已经够拼一辆车了，只是没拧到一起"。**

你已有的零件：
- **读** → WeFlow ✅
- **想** → Codex / Claude Code / DeepSeek-Harness ✅（都在桌面）
- **手机遥控** → claude-remote-control（荣耀手机 App 都做好了）✅
- **AI 中转** → LiteLLM-DeepSeek-Bridge ✅
- **语音** → SenseVoice 模型 ✅

**缺的只有最后一块：把它们串起来的那根线。**
