## 三、★★ 被这些数字推翻的三条结论

### 1. 🔴 「母亲 142 条 ≠ 关系淡」→ **反了**

**旧结论**（[[情绪成本与关系熵]] 缺陷 5）：与父母同住，微信只是事务渠道 → 「女儿 142 条不是关系淡」

**实测**：**母亲 = 全库第 1 大私聊会话（16,538 条）**

```
全库私聊 TOP 6：
  1. 刘丽萍（母亲）      16,538  2024-12-30 → 2026-10-09
  2. 陈晔（导师）         7,282  2025-02-24 → 2026-10-08
  3. 笑一                 6,661  2026-05-08 → 2026-10-09
  4. 文件传输助手          6,558  2024-11-14 → 2026-10-09
  5. 陈昶文               6,382  2025-12-13 → 2026-10-08
  6. Eloise              5,660  2024-11-21 → 2026-09-09
```

→ **新结论**：**母亲和导师是他微信里最大的两个人**（合计 23,820 条）。
→ 「微信测不了同住关系」这句话**本身没错，但用 142 条当证据是错的** —— 142 条是旧导出的截断值。
→ 真实图景：**母亲是微信第一联系人，且到 10-09 仍每日多轮**（10-08/10-09 就 161 条）。
→ ⚠️ **不得**因此把母亲读成「控制」或把本人读成「啃老」—— 事实是**关系密度全库第一**。

### 2. 🟡 「两档结构 249~352 条」→ **区间要改**

**旧**：第一档 1,699~6,275 vs 第二档 249~352

**实测**：第二档里的 **高晓斌 = 1,035**（不是 352）

| 档 | 旧区间 | **新区间** |
|---|---|---|
| 第一档（练手） | 1,699 ~ 6,275 | **2,901 ~ 6,661** |
| 第二档（可结婚） | 249 ~ 352 | **249 ~ 1,035** |

→ **核心结论仍成立**（时间花在不想娶的人身上），但**间距从「5~18 倍」缩到「3~7 倍」**。
→ ⚠️ **不得**再用「249~352」这个区间 —— 它已被高晓斌的 1,035 打破。

### 3. 🟡 「TOP5 占 45.3%」→ **口径必须标注**

**旧**：TOP5 吃掉 45% 社交时间

→ **两个数都对，但口径不同**：45.3% 是**在 53 人样本内**算的；11.1% 是**全库**口径。
→ ⚠️ 引用时必须写清口径，否则会得出相反结论。

## 三·补 · ★★ 我在本次审计中自己踩的坑（自我纠错 · 必读）

**做这份审计时，我一度把母亲转账算成「397 笔 / 348,350」—— 那是错的。**

```
查询：SELECT ... WHERE content LIKE '%收到转账%'     ← 没过滤 role
结果：397 笔 / 348,350                              ← 双倍值
真相：微信转账在库里每笔记两行（them + me，时间差中位 27 秒）
实测：role=them 200 行 / role=me 199 行
去重：200 笔 / 174,775
```

**而这个坑，[[CON-064 微信转账在导出库里每笔记两行（一行 role=them|CON-064]] 早就裁定过了。**

> [!danger] 两条硬规则
> 1. **「已有裁定」优先于「新查询」** —— 我在做「数字基准审计」时，犯了库里已记录过的错。
> 2. **凡涉及转账 / 红包 / 支付** —— 一律先看 `role`，或先读 `04_工作台/结论/CON-*`。
>
> → 母亲转账**正确值**：**200 笔 / 174,775**（2024-12 → 2026-10-09 去重后）
> → 分年：2024 = 1 笔 / 200 · 2025 = 82 笔 / 49,450 · **2026 = 117 笔 / 125,125**
> → ⚠️ **凡引用必须注明是否去重 —— 两个数字差一倍。**
